# 詳細設計 03 — 階と部屋

- 版: 2026-11-17 / 作成: Claude Code / 状態: **未実装の設計**
- 決定の出典: [DECISIONS.md](../DECISIONS.md) B10・B4。考え方は [GAME_DESIGN.md §3](../GAME_DESIGN.md)
- 数値の根拠: 部屋11個と並び順は [sim/](../sim/README.md) の計算で選んだもの。Unity では未実行、人は未試遊。

## 0. 考え方

- 盤は**手で置いたものを選んで並べる**。無作為に生成しない。理由: 学びを試すには「似ているが違う」盤が要り、無作為な盤は因果を読みにくくする。
- 部屋は「どの方針が効くか」で4種類に分ける。1階の中に同じ種類を続けない。同じ方針を押し続けると途中で終わるようにする。
- 難しさは敵の数値ではなく、**配置と行動順**で作る。

## 1. 遠征の形

| 階 | 戦闘 | 新しく出るもの | 段階 |
|---|---|---|---|
| 1階 | 既存の3戦（`Fixture.Encounter(0..2)`） | 方針は慎重・攻めるの2つ | S1（実装済み） |
| 2階 | R01 → R04 → 泉 → R09 | **バランス**の方針。苔の精と花の精の狙い方 | S2 |
| 3階 | R07 → R02 → 泉 → R05 | 敵3体の部屋。2階の終わりに選んだ遺物（[04](04_RELICS_AND_GEAR.md)）が効く | S2 |
| 4階 | R08 → R06 → 泉 → R10 | 茸の番人、影こうもり（[02](02_ENEMIES.md)。部屋は未作成） | S3 |
| 5階 | R03 → R11 → 泉 → 守護者 | 遺跡の守護者 | S3 |

- 1戦は 18〜37 手。演出の時間割から見積もると 1戦の演出は 24〜51 秒（平均 36 秒。`sim/pacing.py`）で、読む時間と余韻を足して 1戦 60〜90 秒の目安に収まります。試遊で長いと感じる部屋があれば、敵の HP を 2 下げて再計算してください。
- 4階と5階に茸の番人・影こうもりを混ぜた部屋は**まだありません**。[02](02_ENEMIES.md) の検証のやり方で部屋を作ってから、R08・R06・R10 のいずれかと入れ替えます。

### 1.1 階の中の流れ

```
階に降りる（全員 50% 回復）
 → 探索（行き先を託す。既存の FloorTraveller）
 → 部屋に入る → 戦闘 → 勝利（倒れた者が 25% で戻る → 全員 25% 回復）
 → 探索 → 戦闘 → 勝利
 → 泉の部屋（全員 50% 回復）
 → 探索 → 戦闘 → 勝利 → 報酬（遺物を2つから1つ。2階・3階・4階の終わり）
 → 下り階段
```

### 1.2 並び順と seed

**2026-11-17 改訂**: 階の中の順番と泉の時機は、プレイヤーが選ぶ形に変えます（[overall/05](../overall/05_AGENCY.md) §3.3）。下の計算は「順番が決まっている場合」のもので、**初回の遠征（導入を終える前）の既定の道**としてだけ使います。2回目以降は、seed が「どの2部屋が先に見えるか」を決め、順番はプレイヤーが決めます。

部屋の順番を入れ替えると、HP の持ち越しのせいで成立しなくなる並びがあります。計算した結果:

| 並び（2〜5階の階内の順番、全 432 通り） | 通り |
|---|---|
| よく考える人が踏破できる | 252 |
| そのうち、倒れる延べ人数が5人以下で、かつ「いつも慎重」「いつも攻める」が踏破できない | **124** |

- **seed が選んでよいのはこの 124 通りだけ**です。一覧は `sim/good_orders.json`（`sim/orders.py` が出力）。`RoomCatalog` に同じ一覧を持たせ、`seed % 124` で引きます。
- 既定の並び（上の表）は一覧の先頭です。S2 の最初の試遊は既定の並びで固定し、seed での入れ替えは2周目以降に出してください。初見の人どうしで比べられなくなるためです。
- 部屋や数値を1つでも変えたら `orders.py` を回し直す。一覧を手で編集しない。

## 2. 部屋の定義

```csharp
namespace RogueTactics.Core.Expedition
{
    public sealed class RoomDef {
        public string Id;                                    // "R01"
        public IReadOnlyDictionary<string,GridPosition> Allies;   // A/B/C/D の初期位置
        public IReadOnlyList<EnemyDef> Enemies;
        public IReadOnlyList<string> Initiative;             // 行動順
        public RoomNote DesignNote;                          // Careful / Bold / Balanced / NeedsCorrection。検査専用
    }
    public sealed class EnemyDef { public string Id; public EnemyKind Kind; public int Hp, Attack; public GridPosition Position; }
    public static class RoomCatalog { public static RoomDef Get(string id); public static IReadOnlyList<string[][]> Orders; }
}
```

- 座標は Core の盤座標（x, y ともに 0〜4。既存の `Fixture` と同じ向き）。下の図は上が y=4。
- 既存3戦も `RoomDef`（`G0`・`G1`・`G2`、敵は `Hunter`）として同じ表に載せ、`EncounterBuilder.Build` が `Fixture.Encounter(i)` と同じ直列化を返すことをテストで固定する。
- `DesignNote` は「満タンの一行ならどの方針で全員生存できるか」という**部屋を選ぶための物差し**で、部屋の正解ではありません。一行の状態が変わると最善の方針は変わります（`sim/answers.py`: 14 部屋すべてで変わる）。表示にもプレイヤー向けの文言にも一切使わない。テストと検査にだけ使う。

## 4. 部屋を足すとき

1. `sim/rooms.py` の敵の種類と数値の範囲を必要に応じて広げ、実行する。方針ごとに候補が出る。
2. 条件で絞る（[overall/05](../overall/05_AGENCY.md) §3.4 の物差しも足す: 一行の状態8通りで最善の方針が3通り以上に変わること。`sim/answers.py`）: 味方と敵が初手で隣り合わない（読む間を作る）。12〜44 手。間違えても倒れるのは原則1人まで（学びであって全滅ではない。いまの一覧では R11 の慎重だけ2人倒れる）。
3. `sim/pick.py` で選び、`sim/floors.py` で遠征を通し、`sim/orders.py` で並びを確かめる。
4. Core に `RoomDef` を足し、方針ごとの生存者数を EditMode で固定する。計算と実装の結果が違ったら、実装ではなく**差の原因**を調べる（計算スクリプトは Core の写しなので、どちらかが規則を読み違えている）。

## 5. 泉と報酬の部屋

| 部屋 | 起きること | 表示 |
|---|---|---|
| 泉 | 入ると全員 50% 回復。1回だけ | 水面の光が一行に上がる。回復の数字を1人ずつ出す（既存の回復演出を流用） |
| 報酬 | 遺物を2つ見せ、1つ選ぶ。選ばずに進むこともできる | [04](04_RELICS_AND_GEAR.md) §4 |
| 下り階段 | 階を降りる。全員 50% 回復 | カメラが引いて次の階へ |

- 泉も報酬も Core の状態遷移（`ExpeditionState` の更新）として実装し、Presentation が勝手に HP を書き換えない。
- 泉の位置は戦闘2と戦闘3の間。場所を変えると §1.2 の計算が変わる。

## 6. 探索との関係

- 既存の `FloorMap` は8部屋と通路を1枚持っています。部屋 0・1・2 が1階の3戦に対応しています（`GauntletRooms`）。
- 2階以降も**同じ形の地図を使い回さない**でください。階ごとに部屋の並びと通路を変えます。ただし地図そのものの作り込みは優先度が低いので（[GAME_DESIGN.md §2](../GAME_DESIGN.md)）、S2 は次の最小構成で足ります。

| 階 | 地図 | 部屋の割り当て |
|---|---|---|
| 1階 | 既存の `FloorMap` | 0・1・2 が戦闘 |
| 2〜5階 | 一本道＋分岐1つ。部屋5つ（戦闘3、泉1、階段1） | 戦闘の順番は §1 の表。分岐の先は泉 |

- `FloorMap` の生成子を `FloorMap(FloorDef def)` に一般化し、既存の配置は `FloorDef.First` として残す。既存の探索テストはそのまま通ること。
- 戦闘の盤（5×5）を部屋の中央に置く計算は既存の `GauntletRooms.Origin` を使う。部屋は 7×7 以上にする。
