# 詳細設計 04 — 遺物と装備

- 版: 2026-11-17 / 作成: Claude Code / 状態: **未実装の設計**
- 決定の出典: [DECISIONS.md](../DECISIONS.md) B9。考え方は [GAME_DESIGN.md §6](../GAME_DESIGN.md)
- 数値の根拠: 遺物6種は [sim/](../sim/README.md) の `relics.py` で、14戦×3方針の結果がどう変わるかを数えたもの。遺物を持った状態での遠征全体は未計算。装備は未検証。

## 0. 考え方

- **数字が大きくなる成長は入れない**（B9）。Lv、攻撃力+1、最大 HP+2 のような報酬は作りません。理解して勝ったのか、強くなって勝ったのかが分からなくなるためです。
- 遺物は**規則を1つ書き換える**もの。書き換えた結果、仲間の動きか、効く方針が変わること。
- **得と損の両方がある**ものを混ぜる。持つと必ず得をする遺物ばかりだと、選ぶ意味が無くなる。
- 効果は必ず Core を通る。Presentation が結果を書き換えない。遺物は隠れて効かない。効いた瞬間に画面で分かること。
- ゲームは「こちらがおすすめ」と言わない。

## 1. 仕組み

```csharp
namespace RogueTactics.Core.Expedition
{
    // 戦闘の規則の定数を1か所に集める。既定値は現行の Core と同じ。
    public sealed class RuleSet {
        public int CounterDamage = 2, GuardReduction = 3, ProtectRange = 1;
        public int HealCharges = 2, HealAmount = 4, HealRange = 2;
        public int FlankBonus = 2; public bool FlankWithAnyAlly = false;
        public RuleSet With(IEnumerable<string> relics);   // 遺物を順に当てた写しを返す
    }
}
```

- いま `Resolve` と `PlanFor` に直書きされている数字（2・3・4・距離1・距離2）を `RuleSet` から読むように変える。`EncounterState` が `RuleSet` を持つ。
- 既定の `RuleSet` のときは直列化に何も足さない。違うときだけ末尾に `|rules:counter=3,…` を足す。既存の hash は変わらない。
- `Rules.Threatened` と守りの判定も同じ `RuleSet` を読むこと（危機の判定と実際の被害がずれないように）。
- 遺物は遠征の間だけ持つ。遠征をまたいで持ち越さない。

## 2. 遺物の一覧（S2 の6種）

「変化」は、14戦×3方針の 42 通りのうち、遺物なしと比べて生存者数が増えた数 / 減った数です（満タン、修正なし）。

| 遺物 | 書き換える規則 | 変化 | 方針ごとの増減 | 画面で分かること |
|---|---|---|---|---|
| 荊棘の護符 | シロの反撃 2 → 3 | +10 / −0 | 慎 +2、攻 +4、バ +4 | 反撃の数字が 3。護符の棘が反撃の光に混じる |
| 見張りの灯 | モモが**2マス先から**シロを守れる | +6 / −1 | 慎 +4、攻 0、バ +2 | モモが離れた位置で盾を構え、光の帯がシロへ伸びる |
| 花盾の紋 | 守りの軽減 3 → 4 | +3 / −0 | 慎 +2、攻 0、バ +1 | 軽減の数字が「−4」 |
| 連携の輪 | ガルの挟撃が、**誰の隣の敵でも**成立する（いまはシロの隣だけ） | +6 / −0 | 慎 +1、攻 +2、バ +3 | 挟撃の金の斬撃が出る回数が増える |
| 朝露の雫 | 回復が 2回×4 → **1回×6** | +9 / −3 | 慎 +1/−2、攻 +3、バ +5/−1 | ミャルの回復が1回きり。光が大きい |
| 巡礼の鈴 | 回復が 2回×4 → **3回×3** | +6 / −7 | 慎 +2/−5、攻 +1、バ +3/−2 | 回復が小刻みに3回 |

読み取れること:

- 荊棘の護符と連携の輪は「攻める」「バランス」を後押しする。見張りの灯と花盾の紋は「慎重」を後押しする。
- 朝露の雫と巡礼の鈴は得と損が割れる。巡礼の鈴は「慎重」と組むと悪くなる盤が多い（1回の量が減り、守りながら持ちこたえる時間が足りなくなる）。**これは欠陥ではなく、選ぶ意味**です。
- 花盾の紋は効く場面が少ない（3通り）。見張りの灯と並べると見劣りするので、組にするときは別の系統と並べる（§4）。

### 不採用にした案

| 案 | 理由 |
|---|---|
| 荊棘 反撃 2 → 4 | 42 通り中 15 通りで生存者が増え、減る場面が無い。持つだけで勝てる |
| 遠見の葉（回復が3マス届く） | ミャルが近づかなくなり、+1 / −2。得が見えにくい |
| 花盾 守り 5・反撃 0 | +2 / −15。ほぼ罠 |

## 3. 遺物の型

```csharp
public sealed class RelicDef {
    public string Id;            // "thorn_charm"
    public string NameKey;       // 表示名は Presentation の対応表
    public Action<RuleSet> Apply;
    public RelicLean Lean;       // Careful / Bold / Mixed。組を作るときと検査にだけ使う。表示しない
}
```

| Id | 表示名 | `Apply` | `Lean` |
|---|---|---|---|
| `thorn_charm` | 荊棘の護符 | `CounterDamage = 3` | Bold |
| `watch_lantern` | 見張りの灯 | `ProtectRange = 2` | Careful |
| `petal_crest` | 花盾の紋 | `GuardReduction = 4` | Careful |
| `ring_of_accord` | 連携の輪 | `FlankWithAnyAlly = true` | Bold |
| `dawn_dew` | 朝露の雫 | `HealCharges = 1; HealAmount = 6` | Mixed |
| `pilgrim_bell` | 巡礼の鈴 | `HealCharges = 3; HealAmount = 3` | Mixed |

- 朝露の雫と巡礼の鈴は同じ値を書き換えるので、**同時に持てない**。片方を持っていたら、もう片方は報酬に出さない。
- 見張りの灯: `ProtectRange = 2` は「守りを宣言できる距離」と「守りが有効な距離」の両方に効かせる（`IsLegal` の `Protect`、`Resolve` の `guarded`、`Threatened` の3か所）。1か所でも漏れると危機の表示と実際の被害がずれます。

## 4. 報酬の出し方

| 時機 | 出す組（seed で左右を入れ替える） |
|---|---|
| 2階の終わり | 見張りの灯 / 荊棘の護符 |
| 3階の終わり | 花盾の紋 / 連携の輪 |
| 4階の終わり | 朝露の雫 / 巡礼の鈴 |

- 組は必ず**傾きの違う2つ**。「慎重寄り」と「攻め寄り」を並べると、プレイヤーは自分のやり方に合わせて選ぶことになる。
- 選ばずに進める。選ばなかった遺物は戻ってこない。
- 画面: 盤の上に遺物を2つ並べる。名前、絵、**書き換える規則を1行**（例:「モモが2マス先からシロを守れる」）。数値の比較表、おすすめの印、色での優劣は出さない。カードの下の主操作は「これを持つ」と「持たずに進む」。
- 盤の上の絵は実装済み（表示だけ、2026-11-19）: `HqRewardAltar.Build(親, 左の床, 右の床, 左の Id, 右の Id, カメラ, vfx)`。同じ石・同じ高さの台座2つに遺物が浮き、同じ間隔できらめく（優劣を見せない）。`Choose(index, 隊の中心)` は選んだ遺物が隊へ飛んで光に包まれ、**届く秒（0.75）を返す**ので、その秒に Core へ渡す。もう一つは 0.4 秒で消える。`Decline()` は両方が消える（0.4 秒）。二度目の答えは無視。名前と1行の規則と主操作（「これを持つ」「持たずに進む」）は UI 側。確かめ: PlayMode `GfxRewardAltarTests`（`RT_GFX_CAPTURE=1` で `unity/Logs/hq/private/reward/`）。
- S2 は3階までなので、S2 で効果を見られるのは2階の終わりの1組だけです。S2 の試遊ではここを観察してください（選んだ理由を自分から話すか）。

## 5. 表示

- 持っている遺物は、盤の右上（小地図の下）に小さな印を縦に並べる。最大3つ。タップで1行の説明。
- 遺物が効いた瞬間に、その印が 0.3 秒光る。出典は `BattleEvent` の派生値に足す `Relic`（効いた遺物の Id。無ければ空）。Presentation が「たぶんこの遺物」と推測しない。
- 絵は実装済み（表示だけ、2026-11-19）: `Presentation/Gfx/HqRelicArt.cs`。`Icon(relicId)` が 132px（44pt×3）の Texture2D、`Sprite(relicId)` が UI 用、`Accent(relicId)` が縁の色。RelicDef.Id と `HqRelicArt.Ids` を一致させること（未知 id は `ArgumentException`。黙って別の絵を出さない）。確かめ: PlayMode `GfxRelicSpringGalleryTests.RelicIconsAreFilledAndToldApartBySilhouette`。
- 演出の差し替えは [CRAFT_HANDBOOK.md §5](../CRAFT_HANDBOOK.md) のレシピを1つ足す形で。例: 見張りの灯は `Shield` の前に、モモからシロへ `Streak` を3本。

## 6. 装備（S3。未検証）

装備は「仲間1人の役割のふるまいを取り替える」ものとして設計します。遺物が一行全体の規則を変えるのに対し、装備は1人の動き方を変えます。

| 仲間 | いまの型 | 取り替え候補 | 変わること |
|---|---|---|---|
| ミャル | 葉の弓（回復役。攻 2） | 茨の弓 | 回復しない。攻 2 → 4。花の精を先に落とせる盤で効く |
| ガル | 大剣（挟撃 +2） | 双剣 | 挟撃なし。倒した直後にもう1歩動ける |
| モモ | 花の盾（シロを守る） | 蔦の盾 | 守る相手が「HP が最も低い味方」になる |
| シロ | 星の杖（反撃 2） | 月の杖 | 反撃しない。攻 5 → 6 |

- 1人1枠。遠征の前に選ぶ。遠征の途中では変えない。
- どれも**数値は未検証**です。入れる前に `sim/core_sim.py` に役割ごとの切り替えを足し、[03](03_DUNGEON_AND_ROOMS.md) の全部屋と並びを計算し直してください。装備で「どの方針でも全員生存」になる部屋が出たら、その装備は強すぎます。
- 見た目: 武器だけ差し替える絵が要ります。原画の追加は Human の判断です（[GAME_DESIGN.md §14](../GAME_DESIGN.md) の8）。原画が無いうちは実装しない。
- 射程（[DECISIONS.md](../DECISIONS.md) N1）が決まると、ミャルとシロの候補は作り直しになります。

## 7. テスト

- 遺物なしの結果は、`RuleSet` を入れる前と hash が一致。
- 遺物ごとに、効果が出る最小の盤を1つ固定（例: 見張りの灯で、モモが距離2から守って被害が減る）。
- `sim/relics.py` の表と同じ増減が、Core で数えても出る。
- 朝露の雫と巡礼の鈴が同時に持てない。
- 危機の判定（`Threatened`）と実際の被害が、全遺物・全部屋で一致する。
