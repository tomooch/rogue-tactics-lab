# 詳細設計 06 — 保存・記録・設定

- 版: 2026-11-17 / 作成: Claude Code / 状態: **未実装の設計**
- 決定の出典: [DECISIONS.md](../DECISIONS.md) B11・B12
- いまの実装: 保存は何もありません。アプリを閉じると遠征も記録も消えます。「演出を減らす」に当たる切り替え（`reducedEffects`、`HqProductHud.cs`）だけは既にありますが、保存されません。

## 0. 考え方

- **端末の中だけ**。サーバーに送らない。解析もテレメトリも入れない。予想メモは端末の外へ出さない。
- **状態ではなく入力を保存する**。Core は決定論なので、入力列を最初から再生すれば必ず同じ状態に戻る。保存の形が規則の細部に依存しなくなる。
- 保存に失敗しても遊べること。読めない保存は捨てずに脇へ退け、新しく始める。

## 1. 何を保存するか

| ファイル | 中身 | 書く時機 | 場所 |
|---|---|---|---|
| `settings.json` | 設定（§4） | 変更したとき | `Application.persistentDataPath` |
| `expedition.json` | 進行中の遠征（§2） | 戦闘の開始・修正を使ったとき・戦闘の終わり・泉・報酬・階の移動 | 同上 |
| `records.json` | 終わった戦闘の記録（§3）。直近 200 件 | 戦闘の終わり | 同上 |

- `PlayerPrefs` は使わない。3つとも同じ仕組み（JSON ファイル）にして、テストを1通りで済ませる。
- 書き込みは「一時ファイルに書く → 名前を付け替える」。途中で落ちても壊れた保存が残らない。
- iOS では `persistentDataPath` は端末のバックアップに含まれます。含めたくない場合の設定は Human の判断（未決。初期方針は含める）。

## 2. 進行中の遠征

```json
{
  "format": 1,
  "rules": 3,
  "seed": 20261117,
  "order": 0,
  "floor": 2,
  "step": 1,
  "party": { "A": 13, "B": 15, "C": 6, "D": 3 },
  "relics": ["watch_lantern"],
  "fountainUsed": false,
  "battle": {
    "room": "R04",
    "policy": 1,
    "commands": ["1", "1", "target:C,Y", "1"],
    "note": ""
  }
}
```

| 項目 | 意味 |
|---|---|
| `format` | この JSON の形の版 |
| `rules` | Core の規則の版（§5）。違う版の保存は再生しない |
| `seed` / `order` | 並び順を決めた seed と、`RoomCatalog.Orders` の何番目か |
| `floor` / `step` | 何階の、何番目の部屋か |
| `party` | **戦闘に入る前**の HP。戦闘中の HP は保存しない |
| `battle.commands` | `Replay` が記録している入力列と同じ書式（方針の番号、`target:` など）。戦闘中でなければ `battle` は無い |
| `battle.note` | 予想メモ。任意 |

**戦闘の途中からの再開**: `party` と `room` と `relics` から `EncounterBuilder.Build` で初期状態を作り、`commands` を先頭から順に当てる。演出は流さず、最後の状態から続きを始める。画面には「続きから」と1行だけ出す。

**再開できないとき**: `rules` が今の版と違う、部屋の Id が無い、入力が不正で `Replay` が例外を出した、のどれか。このときは遠征を「その階の最初、`party` の HP」から始め直す。黙って消さず、「前回の続きは再開できませんでした」と1行出す。

## 3. 記録

```json
{ "format": 1, "items": [
  { "when": "2026-11-17T06:02:11Z", "rules": 3, "room": "R04", "floor": 2,
    "policy": 1, "corrected": 0, "note": "ガルが先に花を落とすはず",
    "outcome": "Victory", "survivors": 4, "hp": "A:13 B:15 C:6 D:0", "steps": 18,
    "hash": "…" } ] }
```

- いまの `MobileTrial`（`MobileG1Session.cs`）が持っている項目に、部屋・階・日時・修正を足した形です。`MobileTrial` をこの形に広げ、`Session.Trials` を記録の読み書きの口にします。
- 200 件を超えたら古い順に捨てる。
- **使い道**（[GAME_DESIGN.md §3.2](../GAME_DESIGN.md) の「振り返る」）: 同じ部屋に2回目に入ったとき、前回の自分の方針・予想・結果を、戦闘前の画面に1行で出す。開かなくても進める。
- 「前回はこうだったから今回はこうしよう」をゲームから言わない。事実を並べるだけ。
- 記録の画面（右上の「記録」ボタン）: 新しい順の一覧。部屋の図、方針、結果、予想メモ。並べ替えや集計は S3 では作らない。
- 規則の版が違う記録は「昔の規則での記録」と薄く表示するだけにする。再生しない。

## 4. 設定

| 項目 | 値 | 初期値 | 効くところ |
|---|---|---|---|
| 効果音の音量 | 0〜100 | 80 | [05](05_AUDIO.md) |
| 環境音の音量 | 0〜100 | 60 | [05](05_AUDIO.md) |
| 演出を減らす | 入 / 切 | OS の「視差効果を減らす」に合わせる | 下の表 |
| 早送り | 1倍 / 2倍 | 1倍 | 下 |
| 触覚 | 入 / 切 | 入 | 主操作と命中 |
| 予想メモ欄を最初から開く | 入 / 切 | 切 | 戦闘前の画面 |

### 4.1 演出を減らす

既にある `reducedEffects`（設定画面の「描画：通常／軽量」）を広げます。いま切り替わるのは、環境の影（`AmbientOcclusion`）、ポスト処理、環境の粒（`HqAmbient.SetReduced`）の3つです。キャラ・エフェクト・数字には効いていません。

| 項目 | 通常 | 減らす |
|---|---|---|
| ヒットストップ | 0.06〜0.10 秒 | なし |
| 着弾の白い光と放射線 | あり | 輪だけ |
| 粒の数 | レシピどおり | 半分（`HqVfx` の発生数に 0.5 を掛ける） |
| 髪・外套の揺れ | あり | なし（骨の二次揺れを止める） |
| 環境の花びら・光の筋 | あり | なし |
| ダメージ数字の跳ね | 1.7 倍から縮む | 跳ねない |
| キャラの縁取りの光（オーラ4サンプル） | あり | なし |

- **Core の結果、イベントの順番、数字の内容は一切変わらない**。変わるのは見た目だけ。PlayMode で、通常と減らすの両方について、表示したイベント列が同じであることを確かめる。
- 性能が足りない端末向けの段階（[IMPLEMENTATION_SPECS.md §7.2](../IMPLEMENTATION_SPECS.md)）とは別の設定にする。こちらは人の好みと体質のための設定。

### 4.2 早送り2倍

- 演出の時間の進みを2倍にする。`HqMotion` の待ち時間は `Time.unscaledDeltaTime` を足し込む形になっているので、足し込む量に倍率を掛ける（`Time.timeScale` は触らない。UI の押下の戻りなどまで速くなるため）。
- パペットの時計（`HqPuppet.Tick` に渡す `dt`）、エフェクト（`HqVfx`）、数字（`HqJuice`）にも同じ倍率を渡す。倍率は `MobileG1View` に1つだけ持つ。
- 危機で止まるのは早送り中も同じ。止まったら倍率に関係なく待つ。
- 音は [05](05_AUDIO.md) §5 のとおり、予備動作の音を省く。
- 2倍より速くしない。「見守る」が主役なので、飛ばすための機能にしない（[GAME_DESIGN.md §13](../GAME_DESIGN.md)）。
- 早送りの状態は設定として残す（次の戦闘でも2倍のまま）。

## 5. 規則の版

Core の結果が変わる変更を入れたら、版を1つ上げます。

| 版 | 中身 |
|---|---|
| 1 | G1（現行。`g1-v1` と直列化の先頭に書かれている） |
| 2 | バランスの方針、苔の精・花の精、HP の持ち越し |
| 3 | 遺物（`RuleSet`） |
| 4 | 茸の番人・影こうもり |
| 5 | 守護者と `RetreatOnce` |

- 版1の戦闘（既存3戦を既定の規則で）は、どの版の Core でも同じ hash を出すこと。版を上げる変更は「足す」だけで、既存の振る舞いを変えない。
- 保存と記録には必ず版を書く。

## 6. テスト

- 書いて読むと同じ内容になる（3ファイルとも）。
- 戦闘の途中の保存から再開すると、保存しなかった場合と最終の hash が一致する。全部屋・全方針・修正ありなしで。
- 壊れた JSON、途中で切れた JSON、未来の `format`、違う `rules` を読ませても落ちず、新しく始められる。
- 200 件を超えた記録が古い順に捨てられる。
- 「演出を減らす」「早送り」のどの組み合わせでも、表示したイベント列と最終状態が同じ。
- 保存ファイルに、端末の識別子・位置・連絡先など、遊びに要らない情報が入っていないこと（項目を列挙して固定）。
