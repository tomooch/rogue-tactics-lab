# 詳細設計 02 — 敵

- 版: 2026-11-17 / 作成: Claude Code / 状態: **未実装の設計**
- 決定の出典: [DECISIONS.md](../DECISIONS.md) B7。考え方は [GAME_DESIGN.md §5](../GAME_DESIGN.md)
- 数値の根拠: 苔の精と花の精は [sim/](../sim/README.md) の計算で確かめた範囲。茸の番人・影こうもり・守護者は**未検証の初期値**です。

## 0. 考え方

敵は「強さ」ではなく「一つの読み」を教えます。1種につき教えることは一つ。数値を上げて難しくしない。難しさは**配置と行動順**で作ります（[03](03_DUNGEON_AND_ROOMS.md)）。

見た目の決まりは全種共通です: 丸い、目が大きい、怖くない、2階調のトゥーン。役割は形と色で分かること（[CRAFT_HANDBOOK.md §4](../CRAFT_HANDBOOK.md)）。

## 1. 仕組み

いま敵の狙いは `Rules.PlanFor` の中に直書きです（A が生きていれば A、いなければ最寄り）。これを駒ごとの頭脳に分けます。

```csharp
public enum EnemyKind { Hunter, Moss, Bloom, Cap, Bat, Guardian }   // Hunter = 現行のふるまい
public sealed class Unit { /* 既存 */ public EnemyKind Kind { get; } }   // 味方は Hunter のまま使わない

internal interface IEnemyBrain { Plan Choose(EncounterState s, Unit self); }
internal static class Brains { public static IEnemyBrain For(EnemyKind k); }
```

- `PlanFor` の敵の分岐を `Brains.For(actor.Kind).Choose(s, actor)` に置き換える。
- **既定は `Hunter`**。既存3戦（`Fixture.Encounter(0..2)`）の敵は `Hunter` のままにする。hash が変わらない。
- 直列化: `Kind` が `Hunter` 以外の駒がいるときだけ、末尾に `|kinds:X=1,Y=2` を足す（行動順の `|order:` と同じやり方）。
- 同点は必ず ID の昇順で解く。乱数を使わない。
- 合法性は今までどおり `Rules.IsLegal` が判定する。頭脳は合法な手しか返さないこと（返せないときは `Maintain`）。

## 2. 苔の精（Moss）— 近い者へまっすぐ

| 項目 | 値 |
|---|---|
| 教えること | 守り手の立ち位置で、誰が殴られるかが変わる |
| 見た目 | 緑の丸い体に双葉（実装済み。`Fixture slime` の緑） |
| HP / 攻 | 14〜18 / 5〜6（部屋ごとに固定。[03](03_DUNGEON_AND_ROOMS.md) の表） |
| 狙い | 生きている味方のうち最も近い者。同点は ID 順 |
| 動き | 隣なら殴る。そうでなければ1歩近づく（既存の `MoveOrMaintain`） |
| 一言の種類 | `HuntNearest` |

現行の `Hunter` との違いは「A を特別扱いしない」ことだけです。A が遠ければ A は殴られません。

## 3. 花の精（Bloom）— 弱っている者を狙う

| 項目 | 値 |
|---|---|
| 教えること | 誰が狙われるかは矢印で読める。弱った仲間を前に出さない |
| 見た目 | 紫の体に五弁の花（実装済み） |
| HP / 攻 | 10〜14 / 4〜5 |
| 狙い | 生きている味方のうち**現在 HP が最も低い**者。同点は距離、次に ID 順 |
| 動き | 隣なら殴る。そうでなければ1歩近づく |
| 一言の種類 | `HuntWeakest` |

HP を持ち越す（B4）と、前の戦闘で削られた仲間がそのまま花の精の的になります。これが持ち越しを「次の戦いに効く」ものにします。

## 4. 茸の番人（Cap）— 動かず、隣を守る

**未検証の初期値**。S2 で入れます。

| 項目 | 値 |
|---|---|
| 教えること | 倒す順番を変えれば守りは崩せる |
| 見た目 | 赤い傘の白い体。ずんぐり。傘が盾に見えること |
| HP / 攻 | 20 / 3 |
| 動き | **移動しない** |
| 行動 | (1) 隣に味方（プレイヤー側）がいれば殴る (2) いなければ「かばう」。隣にいる敵側の仲間全員への被害を、次に自分が動くまで −2 |
| 一言の種類 | `GuardNeighbour` |

- Core への追加: `EncounterState.EnemyGuard`（かばっている番人の ID、無ければ空）。被害の計算で、対象が敵側・番人の隣・番人が生存、なら −2。
- 味方の守り（−3、A だけ）とは別の仕組みとして並べる。両方が同じ一撃に乗ることはない（対象の陣営が違う）。
- イベント: 既存の `EventKind.Protect` を使う。`Actor` が番人、`Target` はかばった仲間のうち ID 最小、`Amount` は 2。
- 読み方の設計: 番人の隣の敵を先に殴ると毎回 2 減らされる。番人自身は攻撃が弱い（3）ので、先に番人を落とすか、番人から離れた敵を狙うのが正解になる盤を作る。
- 検証のやり方: `sim/core_sim.py` に `cap` の頭脳と `EnemyGuard` を足し、`sim/rooms.py` で「番人を先に倒す指定（`TargetOnce`）で全員生存、放置すると1人倒れる」部屋を探す。見つからなければ −2 を −3 に、HP を 16 に動かして再探索。

## 5. 影こうもり（Bat）— 後ろへ飛び込む

**未検証の初期値**。S2 で入れます。

| 項目 | 値 |
|---|---|
| 教えること | 支援役を孤立させない |
| 見た目 | 紫の小さな体に羽。浮いている（影が体から離れている） |
| HP / 攻 | 8 / 4 |
| 狙い | 生きている味方のうち**最大 HP が最も低い**者（いまの一行では D）。同点は ID 順 |
| 動き | 隣なら殴る。そうでなければ「飛ぶ」: 距離2以内の空きマスのうち、狙いに最も近いマスへ。**間の駒を飛び越える** |
| 一言の種類 | `Leap` |

- Core への追加: `ActionKind.Move` の合法条件を、こうもりに限り「距離 2 以内の空きマス」に広げる。行き先の候補は北→東→南→西の順で1歩、次に同じ順で2歩を試し、狙いとの距離が最小のものを取る。同点は先に試した方。
- イベントは既存の `Move`。表示は弧を描いて飛ぶ（`HqCreatureAnim` に跳躍の型を足す。[CRAFT_HANDBOOK.md §4](../CRAFT_HANDBOOK.md) の手順）。
- 読み方の設計: HP が低いので、D の隣に誰かいれば次の手番で落とせる。D が端に1人でいると殴られ続け、3回目で倒れる（D の HP 10、攻 4）。それまでに誰かが届くかどうかの勝負。
- 検証のやり方: 上と同じ。探す条件は「D の初期位置が味方から距離3以上だと D が倒れ、距離1だと全員生存」。

## 6. 遺跡の守護者（Guardian）— 予告してから叩く

**未検証の初期値**。S3 の最後の戦闘です。

| 項目 | 値 |
|---|---|
| 教えること | 危機で止まったときの修正の使いどころ |
| 見た目 | 石と蔦の大型。盤の1マスを占めるが、見た目は2マス分の高さ |
| HP / 攻 | 40 / 8（範囲） |
| お供 | 苔の精 1体（HP 14、攻 5） |
| 動き | 移動しない。盤の中央寄り (2,3) に立つ |
| 行動 | 「予告」と「叩く」を交互に。最初の手番は予告 |

**予告**（`Telegraph`）: 自分を中心にした十字（上下左右に2マスずつ、計8マス）と、斜め4マスのどちらかを選んで宣言する。選び方は「いま味方が多く乗っている方」。同数なら十字。被害は出ない。

**叩く**（`Strike`）: 宣言したマスに立っている味方全員に 8。A への一撃は B の守りで −3 される（既存の規則）。反撃は出ない（隣接の一撃ではないため）。

- Core への追加: `EncounterState.Telegraphed`（予告されたマスの一覧。無ければ空）。`Plan` に `IReadOnlyList<GridPosition> Area` を足す（`Serialize` には、空でないときだけ末尾に追加）。
- **仲間は予告を見て自分では逃げません**（S3 の初期方針）。逃がすのはプレイヤーの修正です。そのために修正の種類を1つ足します。

```csharp
// Replay に追加。接敵ごとの1回を使う。
public void RetreatOnce();   // 次の一巡、味方全員が「予告マスの外で最も近い空きマス」へ1歩動く
```

- 危機停止: 予告が出た最初の1回、`PauseReason.GuardianTelegraph` で止まる（[01](01_CORE_RULES.md) §7）。2回目以降の予告では止まらない。修正は1回しかないので、「最初の予告で使うか、後に取っておくか」が読みどころになる。
- 計算上の目安: 守護者の HP 40 に対し、味方4人の1巡の合計は最大 5+4+4+2+挟撃2 = 17。お供を片付けてから3巡弱。その間に「叩く」は1〜2回来る。全員が範囲に入ったまま受けると 8×4 で、D（HP 10）と C（HP 12）は2回で倒れる。
- 検証のやり方: `sim/core_sim.py` に予告と `RetreatOnce` を足し、「修正なしだと2人以上倒れる。最初の予告で退くと1人、2回目まで待って退くと0人」のような差が出る数値を探す。出なければ攻 8 を 7〜9 で動かす。

## 7. 敵の値のまとめ

| 種類 | HP | 攻 | 動く | 狙い | 段階 | 根拠 |
|---|---|---|---|---|---|---|
| Hunter（現行） | 11〜22 | 4〜7 | 1歩 | A。倒れたら最寄り | S1（実装済み） | 既存テスト |
| 苔の精 | 14〜18 | 5〜6 | 1歩 | 最寄り | S2 | 計算で確認 |
| 花の精 | 10〜14 | 4〜5 | 1歩 | HP 最小 | S2 | 計算で確認 |
| 茸の番人 | 20 | 3 | しない | 隣の味方。いなければかばう | S2 | 未検証 |
| 影こうもり | 8 | 4 | 2歩・飛び越え | 最大 HP 最小 | S2 | 未検証 |
| 守護者 | 40 | 8（範囲） | しない | 予告したマス | S3 | 未検証 |

見た目について: 苔の精と花の精は実装済みの2体をそのまま使えます。**既存3戦の敵は見た目が苔と花ですが、ふるまいは `Hunter`**（A を狙う）です。2階以降で同じ見た目の敵が違う狙い方をすると読みを裏切るので、1階の敵も S2 の時点で苔・花のふるまいに揃えるかどうかは、1階の盤を計算し直してから決めてください（揃えると既存の hash とテストの前提が変わります。未決）。

## 8. テスト

- 種類ごとに「狙いの選び方」を単体で固定（同点の解き方を含む）。
- 敵が `Hunter` だけの戦闘は、変更前と hash が一致。
- 番人の「かばう」は番人が倒れた瞬間に消える。こうもりは駒のあるマスに降りない。守護者の予告マスは盤の外を含まない。
- [03](03_DUNGEON_AND_ROOMS.md) の各部屋について、方針ごとの生存者数が表のとおりであること。
