# 詳細設計 05 — 音

- 版: 2026-11-17 / 作成: Claude Code / 状態: **未実装の設計。音はまだ1つも鳴らしていません**
- 決定の出典: [DECISIONS.md](../DECISIONS.md) B6。対応表の元は [IMPLEMENTATION_SPECS.md §5](../IMPLEMENTATION_SPECS.md)
- 根拠: 合成の数値は耳で確かめていない**出発点**です。実装したら必ず実機のスピーカーで聴いて直してください。

## 0. 考え方

- **音もエフェクトと同じく、計算で作る**。エフェクトをテクスチャ無しでシェーダーの数式から描いたのと同じ理由です: 素材の権利を気にしなくてよい、容量が増えない、数値で直せる。
- 音の原因は必ず Core のイベント。鳴らす場所は演出と同じ2か所（予備動作の頭と着弾）。演出と音がずれない。
- **着弾の音の頭を、HP が変わる瞬間に合わせる**。これが手応えの大半です。
- 無音の Core イベントを作らない。
- 絵柄はやさしい。音も丸く、短く、高すぎない。金属の刺さる音、低い爆発、悲鳴は使わない。

## 1. 仕組み

```csharp
namespace RogueTactics.Presentation.Sfx
{
    public enum Cue { /* §3 の表の Id */ }
    public sealed class HqSfx {                       // MobileG1View が1つ持つ
        public void Build();                          // 起動時に全キューの AudioClip を合成して持つ
        public void Play(Cue cue, float gain = 1, float pitchJitter = .06f);
        public void SetBed(Bed bed);                  // 環境音の切り替え（探索 / 戦闘 / 危機）
        public float Master, SfxVolume, BedVolume;    // 設定（06）
    }
    internal static class Synth {                     // pure。UnityEngine に依存しない部分
        public static float[] Render(Patch p, int sampleRate);
    }
}
```

- 合成は起動時に1回。`AudioClip.Create(name, samples, 1, 44100, false)` と `SetData`。実行中に合成しない（GC とカクつきを避ける）。
- `AudioSource` を 8 本持ち回す。同じキューの同時再生は 2 本まで。3本目は一番古いものを止める。
- ピッチを ±6% 揺らす（`pitchJitter`）。同じ音の繰り返しを機械的に聞かせない。揺らぎは**表示用の乱数**で、Core の乱数と混ぜない。
- 呼ぶ場所: `HqPose.KickPoses`（予備動作）と `HqPose.LandPoses`（着弾）。`HqVfx` のレシピを呼んでいる行の隣に1行ずつ。
- 一時停止中は鳴らさない。早送り2倍では間隔だけ詰まり、ピッチは変えない。
- 全キューの合計は 44.1kHz モノラルで約 12 秒、メモリ約 1MB の見込み（未計測）。
- `Synth` は pure C# にして EditMode でテストできるようにする（§6）。

## 2. 合成の部品

1つの音は、次の部品を足し合わせた `Patch` で書きます。

| 部品 | 引数 | 何に使うか |
|---|---|---|
| 正弦 / 三角 | 始まりの高さ Hz、終わりの高さ Hz、長さ | 柔らかい打音、鈴、上昇音 |
| ノイズ | 帯域の中心 Hz、幅、長さ | 風切り、砂、布、水 |
| 包絡 | 立ち上がり ms、減衰 ms、曲がり | すべてに掛ける。打音は立ち上がり 1〜3ms |
| 倍音の鈴 | 基音 Hz、倍率の列（1, 2.76, 5.4）、減衰 | 鐘、鈴、結晶 |
| ピッチの落ち | 始まりから何 ms で何 % 落ちるか | 「ぽん」「ぷるん」の丸さ |
| 低域通過 | 遮断 Hz | 全体を丸める。**最後に必ず 9kHz 以下に** |

音量の決まり: 各キューは合成後に最大振幅を 0.8 に正規化し、§3 の「大きさ」を掛ける。

## 4. 環境音

音楽は未決です（[DECISIONS.md](../DECISIONS.md) N2）。それまでは環境音だけで空気を作ります。これも合成します。

| 層 | 作り方 | いつ鳴る |
|---|---|---|
| 風 | ノイズを低域通過 600Hz。遮断を 0.1Hz の正弦でゆっくり揺らす | 常時。音量 0.25 |
| 水 | ノイズ 2〜5kHz。振幅を 7Hz 前後の乱れで細かく揺らす（滝） | 常時。音量 0.15 |
| 鳥 | 正弦 2.5→3.5kHz の短い上昇 80ms を 2〜3 回。8〜20 秒おき | 探索中だけ |
| 鼓動 | 正弦 60Hz、減衰 200ms。1 秒に 1 回 | 危機で止まっている間だけ。音量 0.2 |

- 4 秒のループを2本（風・水）合成し、つなぎ目は 200ms の交差で消す。
- 戦闘に入ると鳥が止み、風が 0.25 → 0.18 に下がる（静かになることで緊張を作る）。
- 危機で止まると水が 0.15 → 0.05 に下がり、鼓動が入る。「考える間」を音で作る。
- 切り替えはすべて 0.6 秒かけて滑らかに。

## 5. 重なりの決まり

- 命中の瞬間、環境音を 120ms だけ 70% に下げる（命中音を立たせる）。
- `HitGuarded` が鳴るときは通常の命中音を鳴らさない。守れたことが音だけで分かること。
- `Counter` は命中音の 0.10 秒後（ヒットストップが明けた瞬間）に鳴らす。
- 早送り2倍では、予備動作の音を鳴らさず着弾の音だけにする（詰まって濁るため）。
- 「演出を減らす」設定（[06](06_SAVE_AND_SETTINGS.md) §4）では音は減らさない。別の設定（音量）で扱う。

## 6. 確かめ方

1. **数えて確かめる**（EditMode）: `EventKind` × 型の全組み合わせにキューが割り当たっている。割り当ての無い組があればテストが落ちる。
2. **波形で確かめる**（EditMode）: 全キューが、最大振幅 0.8 以下、長さが表の ±10%、最初の 5ms 以内に立ち上がる（着弾音）、末尾が 0 に落ちる（プチッと鳴らない）。
3. **聴いて確かめる**（人）: 実機のスピーカーとイヤホンの両方で。次の5点を見る。
   - 目を閉じて、誰が攻撃したか型を言い当てられるか
   - 守れたときと守れなかったときの違いが分かるか
   - 30 回連続で同じ音を聞いて、うるさくないか
   - 小さな音量でも命中が分かるか
   - 絵柄に対して硬すぎないか
4. 合成の数値を直したら、何をどう変えたかを [CRAFT_HANDBOOK.md](../CRAFT_HANDBOOK.md) の音の節（新設）に残す。エフェクトの「よくある失敗と直し方」と同じ形で。

## 7. 素材を使うことにした場合

合成で質が足りないと Human が判断したら、素材に切り替えます。その場合の決まり:

- 無料で、権利の明確なもの（CC0 など）だけ。出典と許諾を `provenance.json` に1件ずつ記録する。
- 有料素材、外部サービス、生成 AI サービスの利用は Human の許可が要る。
- `HqSfx.Play(Cue)` の口は変えない。`Build()` の中で「合成する」か「読み込む」かを切り替えるだけにする。
