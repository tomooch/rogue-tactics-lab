# 総合設計 02 — システムの全体図

- 版: 2026-11-17 / 作成: Claude Code
- 位置づけ: 個々の仕組み（[specs/](../specs/)）が**どうつながって1つのゲームになるか**を示す章。新しい仕組みを足すとき、どこに触れ、何を壊しうるかをここで確かめる。
- 数字の出どころ: [sim/](../sim/README.md)。人が遊んだ結果ではありません。

## 1. 全体図

```
┌─ 遠征 ExpeditionState ──────────────────────────────────────────┐
│  seed・並び順   階・何番目   一行の HP（PartyState）   遺物      │
└───────┬─────────────────────────────────────────┬──────────────┘
        │ 部屋を選ぶ（RoomCatalog）                │ 規則を書き換える（RuleSet）
        ▼                                          ▼
┌─ 戦闘 EncounterState ───────────────────────────────────────────┐
│  盤 5×5   駒（HP・攻・位置・種類）   行動順   守りの状態        │
└───────┬─────────────────────────────────────────────────────────┘
        │                     ▲ プレイヤーの入力（Replay）
        │                     │   ・方針（戦いの前）
        ▼                     │   ・修正 1回（方針の変更／狙いの指定／退く）
┌─ 意図 Plan ──────────┐     │
│ 誰が・何を・誰に・なぜ│ ◀──┘ Rules.Intents / Threatened / ShouldPause
└───────┬──────────────┘
        │ Rules.Resolve（合法性の判定を通る）
        ▼
┌─ 出来事 BattleEvent ────────────────────────────────────────────┐
│ Action / Move / Protect / Damage / Heal / Counter / Death / End  │
└───────┬─────────────────────────────────┬───────────────────────┘
        │ 順に描くだけ                     │ 終わったら
        ▼                                  ▼
┌─ 表示 Presentation ───┐         ┌─ 記録 records.json ─┐
│ 矢印・演出・数字・音  │         │ 方針・予想・結果    │──▶ 次に同じ部屋へ来たとき1行
└───────────────────────┘         └─────────────────────┘
        │ 勝利
        ▼
  PartyState.AfterVictory（復帰 → ひと息） → 泉 / 報酬 / 階段 → 次の部屋
```

矢印は上から下への一方通行です。**表示から規則へ戻る矢印はありません。** 戻るのはプレイヤーの入力だけで、それも `Replay` に記録されます。

## 2. プレイヤーが下す判断の一覧

このゲームの「遊び」は、次の判断でできています。判断を足すとき・削るときは、この表を更新してください。

| 判断 | いつ | 1遠征あたり | 判断に使える情報 | やり直せるか | 間違えたときの重さ |
|---|---|---|---|---|---|
| 行き先（探索） | 部屋の間 | 15 回前後 | 小地図、見えている通路 | いつでも | 軽い（遠回り） |
| 方針 | 各戦闘の前 | 14 回 | 全員の矢印、行動順、敵の位置、一行の HP | 始めるまで何度でも | 1人倒れることが多い |
| 予想を書く | 各戦闘の前 | 任意 | 同上 | — | なし |
| 修正を使うか、何に使うか | 危機で止まったとき | 最大 14 回 | 誰が危ないか、矢印、残り HP | 1戦に1回だけ。取り消せない | 全員生存と1〜2人倒れるの差 |
| やり直すか進むか | 各戦闘の後 | 14 回 | 結果、倒れた仲間、次の部屋までの回復 | 進んだら戻れない | 傷んだ一行で次へ入る |
| 遺物 | 階の終わり | 3 回 | 書き換わる規則の1行 | 選んだら変えられない | 遠征の残り全部に効く |
| 装備（S3） | 遠征の前 | 1 回 | 仲間のふるまいの違い | 遠征中は不可 | 遠征全体 |

計算から分かっている重さ:

- **方針**: 14戦のうち 10 戦は「どれか1つの方針なら修正なしで全員生存、他は誰か倒れる」。残り4戦（既存の3戦目、R09、R10、R11）は、どの方針でも修正なしでは誰か倒れる。
- **修正**: 全 14 戦で、修正を1回まで使えば全員生存にできる（始める方針と変える先の組は部屋ごとに違う）。
- **持ち越し**: 同じ方針を押し続けると 11〜14 戦目で全滅する。戦闘ごとに考える人は踏破できる（倒れる延べ 5 人）。
- つまり、**1つの判断の重さは「1人倒れるかどうか」、判断の積み重ねの重さは「踏破できるかどうか」**です。この2段の重さを保ってください。1つの判断で全滅する盤、何を選んでも同じ盤は作らない。

## 3. プレイヤーに見える情報

| 情報 | 見える時機 | 場所 | 出どころ |
|---|---|---|---|
| 全員の「いまの意図」 | 戦いの前、毎手の前 | 盤上の矢印、カードの一言 | `Replay.Intents()` |
| 行動順 | 常時 | 上の帯 | `Initiative`、`Cursor` |
| 味方の HP | 常時 | 足元、カード | 表示済みイベントの `HpAfter` |
| 敵の HP | 常時 | 足元の棒 | 同上 |
| 敵の攻撃力 | **いまは見えない** | — | 提案: 敵の長押し（[01](01_EXPERIENCE.md) §5） |
| 誰が危ないか | 危機のとき | 頭上の「！」 | `Rules.Threatened` |
| 守りが効いているか | 守っている間 | モモからシロへの線、盾の光 | `EncounterState.Guard` |
| 修正の残り | 危機のとき | 主操作の括弧 | `Replay.CorrectionsLeft` |
| 回復の残り回数 | **いまは見えない** | — | 提案: ミャルのカードに葉の印 2つ |
| 持っている遺物 | 常時 | 盤の右上 | `ExpeditionState.Relics` |
| 前回の自分 | 同じ部屋に来たとき | 戦いの前の1行 | `records.json` |
| 先の手（2巡目以降） | **見せない** | — | 意図は「いま」だけ（D3 [実験中]） |
| 結果の予告 | **見せない** | — | 正解を言わないため |

**隠してよいのは未来だけ**です。いまの状態で結果に効くものは、必ずどこかに出す。回復の残り回数は結果に効くのに見えていないので、出すことを提案します **[提案]**。

## 4. 仕組みどうしの噛み合い

仕組みを1つ変えると、ここに書いた相手に波及します。

| 組 | どう噛み合うか | 変えるときの注意 |
|---|---|---|
| HP の持ち越し × 花の精 | 前の戦いで削られた仲間が、次の戦いで花の精の的になる | 回復の規則を変えると、花の精のいる部屋の結果が変わる |
| 方針 × 行動順 | 同じ方針でも、モモが敵より先に動くかどうかで守りが間に合うかが変わる | 行動順は部屋の定義の一部。変えたら部屋を検証し直す |
| 修正 × 危機停止 | 止まらなければ修正を使う機会に気づけない | 止める条件を変えると、修正の価値が変わる |
| 遺物 × 方針 | 見張りの灯は「慎重」を、荊棘の護符は「攻める」を後押しする | 遺物を足したら方針ごとの増減を数える（`sim/relics.py`） |
| 遺物 × 持ち越し | 回復系の遺物は、戦闘内の回復と戦闘間の回復の両方の重みを変える | 遺物つきの遠征全体は未計算 |
| 守り × 敵の狙い | 守りはシロにしか効かない。敵がシロを狙わない（苔・花）と守りは空振りする | これが「慎重が効かない部屋」を作っている。守りの対象を広げると全部屋が変わる |
| 射程（未決）× すべて | 立ち位置が変わり、誰が殴られるかが変わる | 全部屋を選び直す |
| 意図の表示 × すべての規則 | 規則を足すたびに、意図として**読める形**が要る | 矢印と一言で表せない規則は足さない |

最後の行が、仕組みを足すときの関門です。**矢印1本と全角8字で説明できない行動は、このゲームに入れない。**

## 5. 全体を通して変えないこと

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 同じ入力からは同じ結果 | 読みと学びが成り立つ。保存が入力列だけで済む | replay hash |
| 規則は Core だけ | 表示が結果を変えると、信頼が壊れる | Presentation に数値の計算が無いこと |
| 隠れて効くものが無い | 理不尽を作らない | 遺物・守り・挟撃が効いた瞬間に画面で分かる |
| 数字が大きくなる成長が無い | 理解して勝ったのか、強くなって勝ったのかを分けるため | 遠征をまたいで能力値が変わらない |
| 修正は1戦に1回 | 危機の重みを保つ | `CorrectionsLeft` |
| ゲームが正解を言わない | 「次を試したい」を自分の中から出させる | [01](01_EXPERIENCE.md) §6 の禁止事項 |
| 探索と戦闘は同じ場 | 別画面の戦闘にしない **[確定]** | 画面全体を覆う切り替えが無い |

## 6. 覚えることの量

新しい概念を一度に出しすぎないための予算です。1階につき新しい概念は**2つまで**。

| 階 | 新しく覚えること | 累計 |
|---|---|---|
| 1階・1戦目 | 仲間は自分で動く。矢印は意図 | 2 |
| 1階・2戦目 | 方針で結果が変わる。危機で止まり、1回だけ変えられる | 4 |
| 1階・3戦目 | 修正は何に使うかで結果が違う | 5 |
| 2階 | バランスの方針。HP が次の戦いに残る。敵によって狙い方が違う | 8 |
| 3階 | 敵が3体。遺物 | 10 |
| 4階 | 茸の番人（かばう）。影こうもり（飛び込む） | 12 |
| 5階 | 守護者の予告。退く | 14 |

- 2階だけ3つあります。HP の持ち越しは「教える」のではなく、1階の終わりから既に起きていることに気づく形にする（勝利後に HP が「少しだけ」戻るのを数字で見せる。[specs/07](../specs/07_UI_AND_CAMERA.md) §7）。
- 装備と射程を入れるなら、この表に置き場所を作ってから。置き場所が無いなら入れない。

## 7. まだ解けていない緊張

設計の中で、両立が確かめられていない組です。試遊で見るべき点でもあります。

| 緊張 | どちらに倒れると困るか | いまの手当て |
|---|---|---|
| 見守る ↔ 介入したい | 介入が増えると手動の戦術ゲーム。減ると放置ゲーム | 介入は3か所だけ。修正は1回 |
| 読める ↔ 飽きる | 全部読めると作業。読めないと理不尽 | 意図は「いま」だけ見せる。行動順で先を自分で読む |
| 正解を言わない ↔ 迷子になる | 何も言わないと初めての人が止まる | 1階の3戦を導入として作る（[04](04_ONBOARDING.md)） |
| 持ち越しの重み ↔ やり直しの気軽さ | やり直せば持ち越しの損は消せる | やり直しは罰しない。ただし進んだら戻れない |
| 数値成長なし ↔ 遠征を重ねる動機 | 強くならないと続ける理由が弱い | 記録、並び順、遺物の組み合わせ（[03](03_PROGRESSION.md) §5）。**未検証** |
| やさしい絵柄 ↔ 倒れる重み | 重すぎると絵柄に合わない。軽すぎると守りたくならない | 倒れ方は静かに。勝てば起き上がる |

5番目が一番の不確かさです。数値成長を入れないという決定（B9）が、遠征を繰り返す動機を弱める可能性があります。S2 の試遊で「もう1回やりたいか」を必ず見てください（[07](07_PLAYTEST.md)）。
