# 総合設計 06 — 仲間の自律と、軍師・合議への道

- 版: 2026-11-17 / 作成: Claude Code / 状態: **[提案]**。長期構想。S3 の範囲外
- 位置づけ: [GAME_DESIGN.md](../GAME_DESIGN.md) §6.5 の「軍師と合議」を、いまの決定論の Core から**一段ずつ**たどり着ける道筋にしたもの。各段は単独で遊びとして成立し、次の段へ進まなくても製品になること。
- 裏付け: ありません。どの段も、作って人で確かめるまで仮説です。

## 0. 考え方

目指す姿は「仲間が自分で考えて動き、それを見ているのが楽しい」です。軍師や合議は、そのための手段であって目的ではありません。

守ること（[GAME_DESIGN.md](../GAME_DESIGN.md) §6.5 **[確定]（概念）**）:

- 結果を決めるのは Core。考える仕組みが出すのは**構造化された Plan** までで、ダメージや勝敗を直接決めない。
- 同じ入力からは同じ結果。考える仕組みも決定論にする（乱数を使うなら seed から）。
- 軍師は正解を知らない。仲間は軍師に従わないことがある。それは失敗ではない。
- 変化を見せるためだけに戦術を変えない。考え直して変えない、も正しい結果。

## 2. 段 3 — 気質

### 2.1 仕組み

いまの `PlanFor` は「もし〜なら〜する」の決まった順番です。これを「候補の手を全部挙げ、点を付け、一番高い手を選ぶ」形に置き換えます。

```csharp
internal sealed class Candidate { public Plan Plan; public int Score; }
internal static class Mind {
    // 合法な手をすべて挙げる（攻撃できる相手、守れる相手、癒やせる相手、動ける先、待つ）
    static IEnumerable<Plan> Options(EncounterState s, Unit self);
    // 点 = Σ（その手の特徴 × その仲間の気質の重み）。整数。同点は Plan の決まった順で解く
    static int Score(EncounterState s, Unit self, Plan p, Temperament t);
    public static Plan Choose(EncounterState s, Unit self, Temperament t);
}
public sealed class Temperament {     // 仲間ごと。整数の重み
    public int ProtectWeak, FinishLow, StayNearAnchor, AvoidDanger, FocusSameTarget, KeepDistance;
}
```

手の特徴（すべて盤の状態から計算できる整数）:

| 特徴 | 中身 |
|---|---|
| 倒せる | この手で相手の HP が 0 になる |
| 与える量 | 与えるダメージ（挟撃込み） |
| 守れる量 | この手で、次の一巡に味方が受ける被害がどれだけ減るか |
| 癒やせる量 | 回復量（あふれない分） |
| 自分の危険 | 動いた先で、次の一巡に自分が受ける被害 |
| 仲間との近さ | 動いた先から、守られる者までの距離 |
| 同じ相手 | 直前に味方が殴った相手か |

### 2.2 守ること

- **重みを全部 0 にした既定の気質で、いまの `PlanFor` と同じ手が出ること。** そのために、特徴の並びと同点の解き方を、いまの手順（守る → 癒やす → 殴る → 近づく）と一致させる。既存の hash を壊さない。
- 「次の一巡に受ける被害」は、`Rules.Threatened` と同じ読み（いまの意図の合計）で計算する。先を何手も読ませない。読ませると、プレイヤーが仲間の考えを追えなくなる。
- 気質は**数個の重みだけ**。大きな表や学習済みのモデルにしない。プレイヤーが「この子は仲間が傷つくのを嫌がる」と言葉で言える範囲に保つ。

### 2.3 遊びとしての意味

- 方針（慎重・バランス・攻める）は、モモの気質の重みを一時的にずらす頼みごとになる。いまの3つは、その特別な場合。
- 「方針を持つ者を選べる」（[specs/01](../specs/01_CORE_RULES.md) §3）が自然に入る: 誰に頼んでも、その仲間の気質の上でずれる。
- 装備（[specs/04](../specs/04_RELICS_AND_GEAR.md) §6）は、気質と手の候補を取り替えるものとして整理できる。

### 2.4 作る前に確かめること

`sim/core_sim.py` に `Mind` を写し、次を計算で確かめてから Core に入れる。

- 既定の気質で、14 戦×3 方針の結果がいまと完全に一致する。
- 気質を1つ動かしたとき、結果が変わる部屋と変わらない部屋の両方がある（全部変わるなら強すぎ、全く変わらないなら意味が無い）。
- どの気質でも、120 手の打ち切りに達しない（お見合いで止まらない）。

## 3. 段 4 — 経験

遠征を重ねる動機（[03](03_PROGRESSION.md) §5）への答えの候補です。数値は増やさず、**ふるまいが1つ増える**。

- 遠征の記録から、条件を満たした連携が1つ「身につく」。例: 「モモが守った直後にガルが挟撃で倒した」が3回起きたら、ガルは「モモが守っている相手の隣の敵」を優先するようになる（気質の重み `FocusSameTarget` が 1 上がる、ではなく、**手の候補が1つ増える**）。
- 身についた連携は、遠征の始めに1行で知らせる（「ガルとモモの息が合ってきた」）。何が変わったかは、戦いの中で見て分かるようにする。
- 身につく連携は、手で作った一覧から。自動生成しない。最初は 4〜6 個。
- 決定論: 記録が同じなら、身につくものも同じ。
- 守ること: 身についた連携で、**どの部屋も無条件で勝てるようにならない**こと（[specs/04](../specs/04_RELICS_AND_GEAR.md) の装備と同じ検査）。

## 4. 段 5 — 軍師の提案

- 軍師 E は盤の外。戦いの前に、役割分担を1つ**提案**する（例:「モモは守り、ガルは右の敵から」）。提案は「各仲間の気質のずらし方」の組として表す。
- 仲間は、提案を受けるか、自分の考えを通すかを決める。決め方は、提案に従ったときの手の点と、自分の気質での点の差が、軍師の**影響力**の範囲内かどうか。整数の比較で、決定論。
- プレイヤーは、軍師の提案を採る／採らない／仲間の案を支持する、を選べる。**どれが正しいかは言わない。**
- 見せ方: 食い違いは長文にしない。表情、小さな吹き出し1つ、矢印の色（軍師の案は金、仲間の案は青）。4人同時の吹き出しは出さない（[GAME_DESIGN.md](../GAME_DESIGN.md) §6.5）。
- 統率力（仲間の自主性を活かす力）と影響力（提案を通す力）は別の値。数値化は未決。

確かめたい問い（実験として）:

- 軍師の提案が外れたとき、プレイヤーは軍師を「使えない」と感じるか、「次はどう言うか」と興味を持つか。
- 仲間が提案を断ったとき、腹が立つか、頼もしいか。

## 5. 外部の AI を使う場合の線引き

将来、言語モデルなどを使って提案や会話を作る場合の決まりです。入れるかどうか自体が Human の判断で、課金・外部サービスの導入は明示の許可が要ります。

- モデルが出してよいのは、**構造化された提案**（気質のずらし方、狙いの優先順）と**台詞**まで。
- 提案は Core の検査（合法性、範囲）を通ってから使う。通らなければ捨てて、既定の気質で動く。
- 戦闘中に呼ばない。戦いの前に1回作り、入力として記録する。こうすれば再生で同じ結果になる。
- モデルの出力を、ダメージ・命中・勝敗の計算に入れない。
- 通信が無くても遊べること。

## 6. 進める順番の判断

段 3 に進む条件を先に決めておきます。

| 条件 | 見るもの |
|---|---|
| S3 までで、「仲間が考えて動いている」と感じてもらえているか | 試遊で、仲間の行動を「この子は〜したかったんだ」と説明するか |
| 方針が3つで足りないと感じられているか | 「もっと細かく頼みたい」が出るか |
| 遠征を重ねる動機が弱いか | [03](03_PROGRESSION.md) §5.2 |

1つ目が「いいえ」なら、段 3 より先に、段 1 と 2 の見せ方を直す。仕組みを足しても、見えなければ意味が無い。
