# 総合設計 07 — 人の試遊

- 版: 2026-11-17 / 作成: Claude Code / 状態: **[提案]**
- 位置づけ: このゲームが面白いかどうかは、人が遊ぶまで分かりません。計算と自動テストが言えるのは「規則が正しい」「選択に意味がある」までです。この章は、試遊を**誰がやっても同じ質で**行い、結果を設計に戻すための手順です。
- 守ること: 解析・テレメトリ・録画の外部送信は入れない（[GAME_DESIGN.md](../GAME_DESIGN.md) §10 **[確定]**）。記録は紙かメモ。agent は試遊の結果を推定しない。

## 1. いつ、何を確かめるか

| 回 | 時機 | 対象 | 主に見ること |
|---|---|---|---|
| S1 | 1階が製品の質になった後。**S2 の実装に入る前** | 1階の3戦（約5分） | 説明なしで遊べるか。見ていて楽しい瞬間があるか。自分から方針を変えるか |
| S2 | 3階まで | 3階までの遠征（約 12 分）と、終わった後 | 方針を「正解当て」と感じるか。道を選ぶか。もう一度始めるか |
| S3 | リリース候補 | 遠征全体（約 20 分）を2回 | 2回目に違うことを試すか。飽きる場所 |

S1 を飛ばして S2 を作らないでください。1階が楽しくないなら、階を増やしても楽しくなりません。

## 2. 誰に

- 1回につき 3〜5 人。**このゲームを見たことがない人。**
- 少なくとも1人は、ふだん戦術ゲームを遊ばない人。
- 開発に関わった人、設計書を読んだ人は数えない。
- 同じ人に2回頼まない（S3 の「2回目」は同じ回の中で）。

## 3. やり方

### 3.1 渡す前

- 端末を渡して言うのは1つだけ:「遊んでみてください。思ったことは、声に出してもらえると助かります」。
- ゲームの説明、操作の説明、目的の説明をしない。
- 隣に座り、画面と顔の両方が見える位置に。

### 3.2 遊んでいる間

- **助けない。** 止まっても、間違えても、聞かれても、「どう思いますか？」とだけ返す。
- 例外: 3分以上まったく進まないとき。そのときは「何を探していますか？」と聞き、答えを記録してから、最小の一言で先へ進める。これは「導入の失敗」として数える。
- 誘導になる相づちを打たない（「いいですね」「そうそう」）。
- 見ている人が書くのは、**起きたこと**と**言ったこと**。解釈は後で。

### 3.3 終わった後

何も言わずに 20 秒待つ（もう一度始めるかを見る）。それから、この順に聞く。先に答えを匂わせる聞き方をしない。

1. いま何が起きていましたか？（自分の言葉で説明してもらう）
2. 誰が印象に残りましたか？ なぜ？
3. 途中で、何か変えたくなった場面はありましたか？
4. 分からなかったところはありますか？
5. 続きがあったら、次は何をしてみたいですか？

「面白かったですか？」は聞かない。たいてい「はい」と返ってきて、何も分かりません。

## 4. 記録用紙

1人につき1枚。丸を付けるだけで済むようにします。

### 4.1 数えるもの（事実）

| 項目 | 記録 |
|---|---|
| 最初の画面から最初の操作までの秒数 | ＿＿秒 |
| 言われずに方針を触った | はい／いいえ（何戦目：＿） |
| 言われずに「もう一度」を押した | 回数：＿ |
| 危機で止まったことに気づいた | はい／いいえ |
| 止まったとき、矢印を見比べた（S1-11 以降） | はい／いいえ |
| 修正を使った | 回数：＿（変えた／続けた） |
| 早送りを使った | 使わない／ときどき／ずっと |
| 画面から目を離した | 回数：＿（どの場面：＿） |
| 仲間を名前で呼んだ | はい／いいえ（誰：＿） |
| 終わった後、言われずにもう一度始めた（S2・S3） | はい／いいえ |
| 2回目に、1回目と違う方針・道・遺物を選んだ（S3） | はい／いいえ |
| 助け舟を出した | 回数：＿（場面：＿） |

### 4.2 書き取るもの（発言と反応）

- 声が出た瞬間（「お」「え」「あー」）と、その直前に画面で起きたこと
- 「なぜ〜したの？」「〜すればよかった」のような、因果についての発言
- 質問（「これ何？」「どうすればいい？」「どれが正解？」）
- 終わった後の5つの問いへの答え（そのままの言葉で）

## 5. 読み方

6つの問い（[GAME_DESIGN.md](../GAME_DESIGN.md) §1）ごとに、合図と目安を置きます。**目安は提案で、最初の試遊の後に見直してください。** 3〜5 人では統計にならないので、数字で合否を決めるのではなく、「同じことが複数の人に起きたか」を見ます。

| 問い | よい合図 | 悪い合図 | 目安 |
|---|---|---|---|
| 1. 見ているだけで楽しい瞬間があるか | 声が出る。身を乗り出す | 目を離す。早送りを押しっぱなし | 過半数に、声が出た瞬間が2回以上 |
| 2. 自分から行動を変えたいと思うか | 言われずに方針を触る | 「何をすればいい？」 | 過半数が、3戦のうちに自分で方針を触る |
| 3. 別のことを試したくなるか | 言われずに「もう一度」。問い5に具体的な答え | 勝ったら進むだけ。問い5に「特に」 | 過半数が、どちらか一方 |
| 4. 説明なしで因果が分かるか | 問い1に、誰が何をしたかを含む説明 | 「なんか勝った」「運」 | 過半数が、守り・反撃・回復のどれか1つを自分の言葉で説明 |
| 5. 可愛さ・動き・UI が続けたい気持ちを高めるか | 名前で呼ぶ。問い2に具体的な仲間 | 色や武器で呼ぶ | 過半数が、名前で呼ぶ |
| 6. テンポを保ったまま操作できるか | 止まったときに迷わず押す | 気づかない。押し間違う | 全員が、止まったことに気づく |

特に見る合図（[05](05_AGENCY.md) §6）:

- **「どれが正解？」と聞かれたら、設計が足りていません。** 1人でも出たら記録し、2人出たら [05](05_AGENCY.md) の変更を見直す。
- 止まったとき、毎回「変える」を押す → 変えるのが正解だと読まれている。
- 止まったとき、毎回「続ける」を押す → 修正の意味が伝わっていない。

## 6. 結果を設計に戻す

| 起きたこと | 戻す先 |
|---|---|
| 導入で止まる、助け舟が要った | [04](04_ONBOARDING.md) §7 の「次の手」 |
| 因果が説明できない | [01](01_EXPERIENCE.md) F1・F2 の見せ方。演出の読みやすさ（[CRAFT_HANDBOOK.md](../CRAFT_HANDBOOK.md) §7 の7点） |
| 「正解当て」と感じられた | [05](05_AGENCY.md) |
| もう一度始めない | [03](03_PROGRESSION.md) §5 |
| 特定の部屋が長い、退屈 | [specs/03](../specs/03_DUNGEON_AND_ROOMS.md)。敵の HP を下げて再計算 |
| 特定の演出が強すぎる、うるさい | [CRAFT_HANDBOOK.md](../CRAFT_HANDBOOK.md) の数値 |

- 試遊の結果（日付、人数、対象の commit、用紙の集計、発言）は、Notion の Tried & Learned が正本です。PR 本文には要約と、それで何を変えるかを書く。個人が分かる情報は書かない。
- **1回の試遊で設計を大きく変えない。** 同じ合図が2回の試遊で続いたら変える。ただし「助け舟が要った」と「どれが正解？」は1回で動く。
- 試遊で直すと決めたことは、[DECISIONS.md](../DECISIONS.md) に Human の決定として記録してから実装する。agent が試遊の結果を読んで勝手に仕様を変えない。

## 7. agent ができること・できないこと

| できる | できない |
|---|---|
| 試遊用のビルドを用意する（Simulator、実機は Human と） | 人の代わりに遊んで「面白い」と判断する |
| 用紙を印刷できる形にする | 試遊の結果を推定して書く |
| 結果の集計を表にする | 「たぶんこう感じる」を証拠として扱う |
| 結果から、設計のどこを直すかの候補を出す | 候補を採用と見なして実装する |
