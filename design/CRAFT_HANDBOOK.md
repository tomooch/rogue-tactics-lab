対象読者: この先を実装する Executor（Codex）。
目的: 「見た目の勘」を持ち込まなくても、同じ品質で作り足せるようにする。判断はすべて数値・手順・確認項目に落としてある。

- グラフィックの仕様一覧 → [GRAPHICS.md](GRAPHICS.md)
- グラフィック以外の実装設計 → [IMPLEMENTATION_SPECS.md](IMPLEMENTATION_SPECS.md)

## 1. 全体の考え方（迷ったらここに戻る）

1. **主役は「仲間が勝手に戦うのを見守る楽しさ」**。画面の仕事は、いま誰が・誰に・何をして・どうなったかを、説明を読まずに分からせること。きれいさはその次。
2. **1つの出来事は「溜め → 当たり → 余韻」の3拍で見せる**。溜めがないと唐突、当たりが弱いと何も起きていないように見え、余韻がないと次の出来事と混ざる。
3. **結果は Core が決め、絵はそれを遅れずに正確に伝える**。演出で結果を変えない、先に漏らさない。HP が減るのは当たりの瞬間ちょうど。
4. **原画と同じ人物に見えることが、技術的な成功より上**。顔・目・色・輪郭は触らない。動かすのは位置・傾き・大きさ・揺れものだけ。
5. **スマホ実寸で見て判断する**。拡大して良く見えても意味がない。390×844 の画面でキャラは高さ約 70pt しかない。
6. **足すより先に、強弱をつける**。全部が光ると何も目立たない。1つの出来事で一番明るいものは1つ。

## 2. アーキテクチャ

### 2.1 層と依存の向き

```
Core（純 C#・決定的）  ──イベント列──▶  Presentation（MobileG1View）──▶ 画面
  RogueTactics.Core.G1                    ├ HqMotion.cs   出来事1件の進行（時間割）
  規則・勝敗・意図・イベント               ├ HqPose.cs     出来事 → 動きと演出の割り当て
                                          ├ HqJuice.cs    数字・HPバーの遅れ表示
                                          └ Gfx/          部品（規則を知らない）
                                              HqPuppet        味方の1枚絵を動かす
                                              HqCreatureAnim  敵（番兵・苔・花）を動かす
                                              HqVfx           エフェクト
```

- 依存は左から右への一方通行。`Gfx/` の部品は Core も `MobileG1View` も参照しない。渡されるのは「どのクリップを何秒で」「どこに何色で」だけ。
- **絵の都合で Core を変えない**。演出に情報が足りないときは Core のイベントに項目を足す提案をする（[IMPLEMENTATION_SPECS.md §1.2](IMPLEMENTATION_SPECS.md)）。Presentation 側で推測して埋めない。

### 2.2 一番大事な技術上の約束: 「測られる物は動かさない」

既存のテストと HUD は、キャラの Renderer の bounds と pawn の Transform から画面上の矩形を計算している（重なり検査、足元 HP、タップ判定）。そこで:

| 動かしてよい | 動かしてはいけない |
|---|---|
| シェーダー内の頂点位置（踏み込み、吹き飛び、伸縮、傾き） | `"Private approved static skin"` と `"Fixture slime"` の mesh・Transform・bounds |
| エフェクト用の別メッシュ | pawn の位置（Move イベントの移動だけは既存どおり pawn を動かす） |
| 顔・冠などの小さな子 Transform | カメラ（揺らすと全矩形がずれる。**画面揺れは入れていない**） |

つまり **見た目の動きは全部シェーダーの頂点ずらし** で作る。攻撃の踏み込みで 1 マス近く移動して見えても、当たり判定用の矩形は元のマスのまま。これがあるので、演出をいくら変えても配置・重なりのテストは影響を受けない。

### 2.3 出来事1件の時間割（`HqMotion.PresentEvent`）

```
t=0            KickPoses(e)   溜めの開始。飛び道具・斬撃は After() で予約
t=duration     Display(e)     ここで初めて HP・状態の表示が変わる
               PopEventNumber 数字が出る
               LandPoses(e)   当たり: のけぞり・白フラッシュ・衝撃・ヒットストップ
+0.26s         余韻（Damage/Counter/Heal/Protect のみ）
+0.14s         次の出来事へ
```

| イベント | duration | 補足 |
|---|---|---|
| Move | 0.52s | pawn 自体が動く。足音ごとに砂ぼこり |
| Damage | 0.62s | 溜め 70% → 振り抜き 30% |
| Counter | 0.50s | 開始時に金色の「割込」の閃き |
| Heal | 0.60s | 術者の足元に陣、対象に緑の柱 |
| Death | 0.72s | 敵は 45% の時点で弾ける。味方は倒れて横たわり、着地で写し（"Fallen rest <id>"）に替わり、土煙と星（§3.3.1） |
| End | 0.20s | 勝利なら花びらと全員の小ジャンプ |

**duration を変えるとき**: 当たりの瞬間は必ず `t=duration`。飛び道具は `After(duration*0.66, Shoot(..., duration*0.34))` のように、発射時刻 + 飛行時間 = duration になるように組む。

## 3. 味方キャラ: 1枚絵パペット（`HqPuppet` + `HqPuppet.shader`）

### 3.1 仕組み

- 承認済みの1枚絵（3:4）を 20×28 の格子メッシュに貼り、**11本の骨**（Root, Body, Head, Weapon, LegL, LegR, CapeL, CapeR, HairL, HairR, Extra）の2Dアフィン変換を頂点シェーダーで合成する。
- 骨は「画像空間」で定義する: x は左右（幅 0.75）、y は足元 0 〜 頭上 1。`HqPuppet.At(u, v)` にテクスチャ座標を渡すと画像空間の点になる。
- 頂点ごとの骨の重みは、骨の線分 A–B からの距離で自動計算（`BuildMesh`）。手で塗らない。
- 鏡像（左右反転）はシェーダーの `_Mirror`。骨の計算は常に原画の向きで行い、最後に反転する。画面方向で指定する値（`Dash`, `Knock`）は `Mirrored` のとき x の符号を返す。

### 3.2 動かし方の決まり

| してよい | してはいけない（Human が不採用にした） |
|---|---|
| Root を丸ごと動かす・傾ける・伸縮する（±10% まで） | 脚の骨を回す・伸ばす（「うにょうにょ」） |
| Weapon を回す（剣を振る、杖を掲げる） | 顔の中を変形させる（目・口の位置が動く） |
| 髪・外套・尻尾をバネで遅らせて揺らす | 伸縮を 0.15 以上かける（別人に見える） |
| 白フラッシュ、金の縁取り | 原画の色を変える（光を掛ける・白へ寄せるのみ可） |

歩きは「体全体が一枚のまま左右に揺れて弾む」代用表現。正式な8コマ歩行（Issue #13）が来たら `Tick` の歩きの塊を UV 切り替えに置き換える。

### 3.3 クリップ一覧と数値

| クリップ | 中身 | 主な数値 |
|---|---|---|
| Attack | 溜め（u<0.7）で後ろに引き、振り抜き（0.7〜1.0）で当てる。近接は `Dash` の分だけ相手へ踏み込み、0.08s 止まってから 0.34s で戻る | 引き = 踏み込み量の 10%。武器の回転 ±0.5〜1.0 rad |
| Cast | つま先立ちで杖を掲げ、着弾で下ろす | 上昇 0.02、縦伸び 3.5% |
| Guard | 足を踏ん張り盾を前へ | 縦 −5%、盾 +14% |
| Hit | `Knock` の向きへ 0.11（画像の高さ比）飛ばされ、小さく浮き、3回揺れて戻る | 減衰 e^(−5t)、0.7s で終了 |
| Cheer | 小さく2回跳ねる | 高さ 0.045 |
| Fall | よろけて Root ごと約 72° 傾き、空いている側へ倒れる | 溶けない（§3.3.1）。向きは `Lean` |
| Rise | 横たわった姿勢から押し上げて立ち、最後に1回跳ねる | 0.9 秒。0.63 秒で足元に回復の光。戦闘だけの build のみ（§3.3.1） |

- **踏み込み量**（`HqPose.Lunge`）= 相手までの床上の距離 − 1.05、上限 2.8（world 単位。1マス = 2.5）。隣のマスなら約 1.45 進み、相手の体に少し重なる所で止まる。重なるくらいでないと「当てた」に見えない。
- 踏み込むのは近接（Blade, Guardian）と敵だけ。Caster と Archer は `Dash = 0`（その場で撃つ）。

### 3.3.1 倒れた仲間（2026-11-17）

倒れても仲間は消えない。勝てば最大 HP の 25% で起き上がる設計（[specs/01](specs/01_CORE_RULES.md) §5）なので、盤の上で横たわって待つ。

- `Fall` クリップは、よろめいて Root ごと約 72°（1.25 rad）傾き、小さく1回弾んで止まる。**溶けて消える処理（`_Dissolve`）は使わない**。
- 着地の瞬間（`LandPoses`）に、その姿勢の写しを `"Fallen rest <id>"` という名前で同じ位置に置く。元のコマは表示側の決まりどおり隠れる（測られる物の一覧から外れる）。写しは測られない。
- 写しは少しだけ色を抜く（`_Color` = (.84, .86, .94, 1)）。光の縁（`_Aura`）と被弾の光（`_Flash`）は 0。
- 生きている誰かが同じマスに立ったら写しを隠す。コマがまた表示されたら（やり直し、次の戦闘）写しを消す。
- **倒れる向き**（2026-11-18）: `Fall` は `HqPuppet.Lean`（±1）で傾く向きを決める。`HqPose.FreeSide` が画面の左右の隣人を数え、**後ろ（画面で上）の隣人は重み 2、手前は 1**、真上・真下の隣人は数えない。軽い側へ倒す（同点は攻撃者から離れる側）。横たわった体は地面の高さにあるので、後ろの者を隠す。手前の者に隠されるほうがまし（戦っている敵を隠さない）。
- **倒れた瞬間の余韻**（2026-11-18）: 仲間には `Vanish`（昇る光と花びら＝去っていく表現）を使わない。着地（`LandPoses`）で `HqVfx.KnockDown`: 体が当たる場所の土煙と床の輪、頭の上を回る小さな星3つ（0.5 秒）。三拍は「よろめき（0〜0.3）・倒れる（〜0.72 秒で着地）・土煙と星」。敵の `Vanish` はそのまま。
- 勝利の演出（`Cheer`）は、立っている仲間だけが行う。
- **勝つと起き上がる**（2026-11-18）。`End`（勝利）を見せた瞬間に、写しごとに専用の `HqPuppet` を作り `Rise` クリップ（0.9 秒）を再生する（`RaiseFallen` / `TickRising`）。`Rise` は `Fall` の終わりの姿勢から、ゆっくり押し上げて直立し、最後に小さく1回跳ねる。同じ支点・同じ剛体の傾きだけを使い、手足は曲げない。立つ間に色を `RestTint` から白へ戻し、0.63 秒で足元に回復の光（`Heal`）を出す。
- 写しが隠れている（誰かがそのマスに立っている）ときは起き上がらない。起き上がると回復の光がその人の足元に出て、別の人が癒やされたように見えるため（2026-11-18 のコマで発見）。次の戦闘で戻る。
- 起き上がるのは**写し**。測られるコマは隠れたまま（Core ではこの戦闘の結果はまだ「倒れた」）。やり直しと次の戦闘（`ResetProjection`）で写しは消える。**起き上がるのは戦闘だけの build（`ExplorationEnabled` が false）だけ**。製品の流れ（`HqExploration`）では、倒れた仲間は勝った後も隊から外れたまま（`FloorExplorationFlowTests.AttackHandoffDoesNotReviveOrMoveDeadCompanion`。立った写しが無いこともそこで assert）なので、横たわったまま残す（2026-11-18 の監査で発見して直した）。25% 復帰（[specs/01](specs/01_CORE_RULES.md) §5）を Core に入れたら、立った写しの下に 25% の HP 表示を出すこと（S2-9）。

### 3.4 新しい味方を足す手順

1. 3:4 の立ち絵（足元が下端から 8% 付近、中央寄せ）を用意する。原画は `_userwork/` から出さない。
2. `HqPuppet.Authored` に `case` を足す。決めるのは **Style**（Blade / Guardian / Archer / Caster）、**Muzzle**（武器の先端）、各骨の Pivot・A・B・Radius。
3. 骨の置き方の目安:
   - Body: 腰から胸。Radius 0.12〜0.13
   - Head: 首を Pivot に、頭の中心まで。Radius 0.20、Strength 1.5（顔が他の骨に引っ張られないよう強くする）
   - Weapon: 握っている手を Pivot に、武器の両端を A・B。Radius 0.045〜0.06、Strength 1.7〜2.0
   - 髪・外套・尻尾: 付け根を Pivot、先端を B。`hang` を 1（上向きの耳や帽子の先は −1）、stiffness 48〜60、damping 5.5〜6（尻尾は 34 / 4.2 で大きくゆっくり）
   - 無い部位は `None(parent)`
4. 確認: 待機・攻撃・被弾のコマを撮り（§7）、**顔が歪んでいないか、武器だけがきれいに回るか**を見る。顔が引っ張られるなら Head の Strength を上げるか、隣の骨の Radius を下げる。

## 4. 敵: 立体トゥーン（`HqCreature` + `HqCreatureAnim` + `HqCreature.shader`）

- 体は自前のメッシュ（`"Fixture slime"`）。**形と Transform は変えない**。生きて見える要素は、2階調のトゥーン陰影・縁の光・カメラを向いた顔・シェーダーでの変形。
- 変形は足元を支点にした5つの値だけ: `squash`（つぶれ）, `lean`（傾き）, `lift`（浮き）, `wobble`（震え）, `dash`（world 位置のずれ）。全マテリアルに同じ値を渡すので、顔や冠も一緒に動く。
- 攻撃: 60% まで縮んで引く → 残り 40% で弧を描いて相手へ跳ぶ → 着地で揺れる → 0.3s で戻る。
- 被弾: つぶれて `Knock` の向きへ 0.55 飛ばされ、ゼリーのように揺れて戻る。目は閉じる。
- 撃破: ふくらんで上から種になって崩れる（`_Dissolve`）。

**見た目は3種類**（`SpiritKind`。2026-11-17）:

| 種類 | 見た目 | ふるまい | いつ出る |
|---|---|---|---|
| `Warden`（金の番兵・碧の番兵） | 淡い青の丸い体、白い石のふた、遺跡の旗と同じ色の八芒星（金＝X、碧＝Y） | シロを狙う（Core の現行の敵、`Hunter`） | 1階 |
| `Moss`（苔の精） | 緑の体に双葉 | 最も近い者を狙う | 2階から |
| `Bloom`（花の精） | 紫の体に五弁の花 | 弱った者を狙う | 2階から |

**決まり: 1つの見た目は1つのふるまい**（[overall/05](overall/05_AGENCY.md) §3.5）。どの敵がどの見た目かは `HqCreature.KindOf(id)` の1か所で決める。名前（`NameOf`）、エフェクトの色（`TintOf`）、指示の画面の顔（`SpiritPortraitGraphic`）も同じ所から引く。Core に敵の種類が入ったら、`KindOf` を名簿（[CODE_BRIDGE.md](CODE_BRIDGE.md) §3）に置き換える。

番兵の星は、カメラを向いた枠に置いた細長い球4本（縦横の長い光線＋斜めの短い光線）と芯で作っている。2本だけだと小さく映ったとき「十字」か「芽」に見えた。体の形と大きさは苔・花と同じ（測られる物を変えないため）。2体は星の色で見分ける。

**新しい敵を足すとき**: 体のシルエットで役割が分かるようにする（丸い = 弱い、尖った = 攻撃的、大きい = 硬い）。色は味方4人の色（青・桃・白銀・若葉）と敵マス（赤）を避ける。顔は必ずカメラ側の面に置く（`Face(x, y)` が楕円体の表面に投影する）。

### 4.x 後の階の敵の見た目（2026-11-18、Core 未対応）

`HqCreature.Build(root, template, kind, alt, camera)` に `SpiritKind.Cap / Bat / Guardian` を渡せば立つ。`HqCreature.KindOf(id)` は今は全員 `Warden` のままなので、S2-2 / S2-10 / S3-2 で Core の敵の種類から `KindOf` を引くように変えるだけでよい（記号は `GlyphOf(kind, alt)`、名前は `NameOf(kind, alt)`、光の色は `TintOf(kind, alt)`）。対応: Core `EnemyKind.Hunter`→`SpiritKind.Warden`、Moss→Moss、Bloom→Bloom、Cap→Cap、Bat→Bat、Guardian→Guardian。`alt` は「同じ戦闘で同じ種類の2体目」（今の `AltOf` は ID が Y）。Warden だけ色（金／碧）が変わり、他の種類は動きの位相だけが変わる。

| 種類 | 形で分かること | 作り | 動き |
|---|---|---|---|
| 茸の番人 `Cap` | 赤い傘が前へ傾き、盾に見える。白い斑点 | ずんぐりした体（`BodyOf` 幅 .62・高さ .34）、傘・ひだ・斑点 | 体のゆれ ×0.6（`Jelly`） |
| 影こうもり `Bat` | 扇に開く羽（指の骨3本＋膜）、立った耳、小さな牙 | 小さい体（幅 .44） | 影から 0.55 浮き、ゆっくり上下（`Hover`） |
| 遺跡の守護者 `Guardian` | 角ばった青灰の石。彫りの帯、苔、額の琥珀の紋 | 超楕円体（`Box` .45、高さ .86・中心 .96）、目は 1.3 倍 | 石なので体のゆれ ×0.25 |

- 体の mesh 名は全種 `Fixture slime`（測る側の約束）。目は全種 `Bright spirit eye` 2つ、口は全種 `Smile`。見張り（S1-13）と重なりの検査が目と口で顔を測るので、新しい種類でも名前を変えない。
- 確かめ方: PlayMode `GfxSpiritGalleryTests`（1戦目の盤で番兵2体の代わりに各組を立たせ、待機と被弾を撮る）。`RT_GFX_CAPTURE=1` で `unity/Logs/hq/private/gallery/` に出す。
- **予告**（守護者）: `HqCreatureAnim.Telegraphing = true` の間、額の紋（`Mark`）が 1.6 倍まで膨らんで白っぽく光り、後ろに光の輪（`Halo`、普段は大きさ 0）が開いて脈打つ。0.25 秒で立ち上がり、false で消える。Core の意図が「次に守護者が範囲を叩く」になったとき（specs/02 §6）に Presentation が立て、着弾で下ろす。範囲のマスの表示は意図の描画（線・アイコン・行き先）の側で作る。
- **予告の範囲**（守護者）: `HqDangerTiles`（`Show(マスの中心の列, マスの大きさ)` → `Strike()` → 0.35 秒で消える、`Clear()`）。黄色寄りの琥珀に斜線の板を、床の石の上面（高さ .05）のすぐ上 .09 に置く。敵のマスの赤・味方の青・選んだ床の金と別の色。描く順は既知のマスの印と同じ透明の 3000（不透明の 2450 だと遺跡の床に隠れた）。マスの一覧は Core の `EncounterState.Telegraphed` / `Plan.Area` だけから渡し、Presentation が決めない。確かめ: PlayMode `GfxDangerRetreatTests`（`RT_GFX_CAPTURE=1` で `unity/Logs/hq/private/danger/`）。
- **退く**（プレイヤーの修正 `RetreatOnce`）: `HqVfx.Retreat(元の足元, 行き先の足元, 色)` が、元に土煙、道筋に低い流れ、行き先に輪ときらめき（0.18 秒遅れ）を出す。仲間の移動そのものは既存の移動の補間に任せる。
- **羽ばたき**（こうもり）: `HqCreatureAnim.Wings` に入れた羽は毎秒約3回（攻撃中は約4回）羽ばたく。葉の揺れとは別。
- 未確認: 実際の戦闘で動かしたときの見え方（Core に種類がないため）、範囲のマスの予告表示、2マス分の高さ（今は約1.5倍）。**S3-2 で守護者を部屋に出す前に、`MobileG1InteractionTests.CheckLayout` / `CheckActorReadability` を守護者の盤で回して板の高さを決め、specs/02 §6 に書く。決まらなければ Human に聞く。**
- 見張り（S1-13）と重なりの検査は、まだ新しい3種を測っていない。S2-10 / S3-2 で部屋に出したら `GfxReadabilityWatchdogTests` の対象にその部屋を足して全件を回す。精の平均しきい値（0.60）を種類ごとに変える必要が出たら、コマを並べて Human に見せる（しきい値を黙って緩めない）。

## 5. エフェクト（`HqVfx` + `HqVfx.shader`）

### 5.1 仕組み

- テクスチャなし。**14種類の形をシェーダーの数式で描く**: Glow, Ring, Sparkle, Crescent, Streak, Petal, Plus, Puff, Shard, Ward, Rune, Pillar, Veil, Burst。
- CPU 側は粒の配列（上限 3000）を毎フレーム1つのメッシュに詰めて1回で描く。Unity の ParticleSystem もアセットも使わない。
- 「光」（加算に近い）と「物」（普通の半透明）を同じパスで描く。出力は乗算済みアルファ。**描く順 = `Emit` した順**。
- `Emit(形, 位置, 初期サイズ, 最終サイズ, 寿命, 初期色, 最終色, ...)`。サイズは world 単位の半径（キャラの背丈は約 3）。

### 5.2 レシピ（組み合わせ）

（`CastCircle` と `Charge` は別の関数なので、表は16行でもレシピは 17）

出来事ごとに、形を重ねた「レシピ」関数を呼ぶ。新しい演出は `Emit` を直接並べず、**レシピを1つ足して `HqPose` から呼ぶ**。

| レシピ | 使う場面 | 重ねているもの（描く順） |
|---|---|---|
| `Impact` | 攻撃が当たった | 暗い暈 → 放射線（`rays`）→ 白い芯 → 十字の閃き → 輪×2（`rings`）→ 火花 16×`rays` → きらめき6 → 欠片5 → 煙3。戦い方ごとの絞り方は §5.3.1 |
| `Slash` | 剣の斬撃 | 暗い暈 → 色の三日月 → 白の三日月 → 細い芯 → 火花7 |
| `Slam` | 鈍器（モモ）と敵の体当たりの着地 | 床を走る輪 → 砂煙8 |
| `Cut` | 剣（ガル）が当たった | 斬った向きの硬い光の線×2 |
| `Blast` | 魔法（シロ）が当たった | 開く陣の輪 → 結晶の破片10 → 色の光6 |
| `Pierce` | 矢（ミャル）が当たった | 対象を抜ける細い線 → 散る葉7 |
| `Shoot` | 魔法弾・矢 | 弾本体 + 尾。到着時刻を指定できる |
| `CastCircle` / `Charge` | 詠唱 | 床の陣 + 光の柱 + 集まる粒 |
| `Shield` | 守護 | 六角模様の半球。打たれると波紋と破片 |
| `Heal` | 回復 | 床の輪 → 緑の柱 → 昇る＋印と粒 |

| `Reaction` | 反撃の割込 | 金の閃き×2 + 輪 |
| `Celebrate` | 勝利 | 花びら 26 + きらめき 14 |

### 5.3 明るい背景で光を見せる方法（今回いちばん効いたこと）

舞台は日向の白っぽい石。ここに白い光を足しても **白の上の白で見えない**。対策は3つ:

1. **先に暗い暈（`Veil`）を敷く**。当たりの周囲だけ 0.3 秒、紺色（`Ink`）を 34〜42% 重ねる。その手前の光が初めて「光って」見える。強い出来事（命中・斬撃・撃破）だけに使う。回復や詠唱には使わない。
2. **光は少しだけ後ろを覆う**。シェーダー末尾で、光のアルファを 0.36 にしている。0 にすると白飛びし、1 にすると濁る。
3. **芯は白、外側はキャラの色**。全部白にしない。色は `TintOf(id)`（シロ=青、モモ=桃、ガル=白銀、ミャル=若葉。敵は `HqCreature.TintOf`: 金の番兵=金、碧の番兵=碧。苔の精=苔色、花の精=紫は2階以降）。

### 5.3.1 4つの戦い方を形で見分ける（2026-11-18）

色だけでは見分けられない（ガルの色は白銀で、白い芯とほぼ同じ）。**形を主役にし、共通の白い放射線と輪は鈍器だけに残す**。`Impact(at,tint,power,rays,rings)` の `rays`（放射線）と `rings`（白い輪）で絞る。

| 戦い方 | 誰 | 主役の形 | `Impact` の絞り | レシピ |
|---|---|---|---|---|
| 鈍器 | モモ、すべての敵 | 丸い白の衝撃＋床を走る輪 | power 1, rays 1, rings 1 | `Slam` |
| 剣 | ガル | 線（振りの三日月＋対象を貫く一閃と火花） | power .8, rays .3, rings 0 | `Cut`（振りの途中に `Slash`） |
| 魔法 | シロ | 術者の色で咲く紋と色の輪 | power .8, rays 0, rings 0 | `Blast` |
| 矢 | ミャル | 細い光の筋が突き抜ける＋若葉 | power .6, rays 0, rings 0 | `Pierce` |

- 確かめ方: `RT_GFX_CAPTURE=3` で撮ると、ファイル名に `Damage_<打った者><打たれた者>` が入る。同じ戦い方のコマを並べ、数字を隠して言い当てられるか見る。
- 2026-11-18 のコマで4種とも形で見分けられた。矢は既定の1戦目では撃たれないので、`RT_GFX_ENCOUNTER=2`（3戦目を最初の部屋で撮る。部屋間の移動は飛ばすので流れの検査ではない）で撮る。矢は最初の版では細すぎたので、若葉色の筋と小さな色の光を足した。
- 敵の攻撃も鈍器と同じ見た目。敵ごとに変えるなら、ふるまいの違う敵（[specs/02](specs/02_ENEMIES.md)）と一緒に。

### 5.4 大きさと時間の目安

| 要素 | サイズ（半径） | 寿命 | 守ること |
|---|---|---|---|
| 白い芯（`Glow`） | 0.4 → 0.9×power | 0.08s | **0.15s を超えない。背丈の半分を超えない**（超えると対象が白い円で消える）。S1-2 で 0.5→1.5・0.12s から弱めた |
| 放射線 | 2.0 → 3.3 | 0.20s | 当たりの瞬間だけ |
| 衝撃の輪 | 0.4 → 2.3 | 0.30s | 広がるほど細くする（k: 0.2→1） |
| 火花 | 0.46 | 0.2〜0.4s | 速度 7〜14、強い減速（drag 6） |
| 暗い暈 | 4.6 → 5.6 | 0.34s | アルファ 0.42 まで |

- **速く始まり、ゆっくり消える**。サイズの補間は減速（`1-(1-t)²`）、消え方は寿命の後半だけ（`fadeFrom`）。
- 1つのレシピの総寿命は 0.5 秒以内（勝利と回復を除く）。次の出来事に被せない。

### 5.4.1 白飛びの自動の見張り（S1-13、2026-11-18）

PlayMode `GfxReadabilityWatchdogTests.ImpactsNeverWashTheStruckFigureOutInWhite`。1戦目と3戦目（矢）を最後まで流し、Damage / Counter が着弾するたびに、**当たった側の顔**を着弾から 0.40 秒（その出来事の余韻の長さ。次の出来事の光は数えない）毎フレーム測る。

- **どこを測るか**: 盤のカメラが描いた絵（`FieldCamera.targetTexture`）。数字や HUD は入らない。顔は `MobileG1InteractionTests.CheckActorReadability` と同じ求め方（味方 = puppet の頭の骨、敵 = 目と口の部品）。そのキャラ自身が塗られている点だけ数える（透明な余白の後ろの白い石は数えない）。
- **何を数えるか**: 「白に近い画素」= sRGB で R・G・B の一番暗いものが 0.90 以上。その割合から、**同じ顔の戦闘前の割合**（シロ 0.155、モモ 0.03、苔の精 0.05〜0.07 など）を引いたものを「白飛び」とする。
- **読み取りで止めない**: 盤のカメラは MSAA なので解像コピーを作り `AsyncGPUReadback` で読む。同期で読むとフレームが 45〜100ms に伸び、`HqVfx` の時計（1フレーム最大 0.05 秒）が遅れて、光が実際より長く見えた（実際に誤った）。

しきい値（実測から。2026-11-18、Unity 6000.3.25f1 batchmode、32 着弾 / うち味方 10）:

| 判定 | しきい値 | 今の演出（実測） | 芯を ×4 の大きさ・×3 の寿命にした場合 |
|---|---|---|---|
| 白飛び 0.60 超えの時間（全員、着弾ごと） | **0.20 秒以内**（手引きの芯の寿命 0.15 秒 + 時計の1歩 0.05 秒） | 最長 0.137〜0.148 秒（シロの魔法が精に当たったとき） | 最長 0.163〜0.185 秒（これだけでは落ちない） |
| 味方の顔の白飛びの最大（着弾ごと） | **0.60 以下**（旧 0.80） | 0.25〜0.50（弱める前 0.44〜0.67） | 最大 0.94〜0.95（落ちる） |
| 味方の顔の白飛びの最大の平均（全着弾） | **0.40 以下**（旧 0.65） | 約 0.32（弱める前 0.557〜0.575） | 0.74〜0.76（落ちる） |

- **精（敵）の顔は1発ごとの最大では縛らず、平均で縛る**（2026-11-18、S1-2 の続き）。体が淡い（一番暗いチャンネルで約 0.85）ので少しの光で 0.90 を超える。以前は魔法・鈍器で目と口が 2〜4 フレームほぼ白くなった（最大 0.95、平均 約0.85）。次のように直した（`HqPose`）:
  - 精に当たる光は、胸（体の中心＝目の位置）から足元へ 40% 下げて置く。
  - 精自身の光（`HqCreatureAnim.Flash`）を 1→0.25。
  - `HqVfx.Impact` に `white`（熱い部分の白さ。0.45 で殴った側の色寄り）、`Blast` に `soft`（魔法の光の大きさと明るさ。0.5）を足し、精に当たるときだけ下げる。鈍器・精同士は `Impact` を ×0.85・放射線 0.6・輪 0.5 に。
  - 加算の光は、淡い体の上では色を付けても白へ飽和する。色ではなく**大きさと明るさ**を下げるのが効いた。
  - 結果: 精の顔の白飛び最大の平均 約0.47（1発ごと 0.26〜0.80）。B の踏み込みの軌跡（白い帯）が横切る1発が一番白いが、体と口は見える。C の剣の線は目の上を通るが目は読める。しきい値は**精の平均 0.60 以下**。
  - 時間の判定（0.60 超えが 0.20 秒以内）は前のまま全員に掛ける。
- 味方の白飛びの最大は 0.5（「背丈の半分」）を超える着弾がある（0.55〜0.67）。切り抜きを見ると、精の体当たりの一番明るいフレームで、白い衝撃と放射線が顔の下半分（目のあたり）に被っている。0.5 を超えるのは着弾ごとに 0.05 秒以内（1〜3 フレーム）。最初はこの演出が通る位置（0.80 / 平均 0.65）にしきい値を置いた。
- **2026-11-18 Human 判断「光を弱めて」**（切り抜き4枚を見て）。精（または鈍器）が**味方**に当たるとき（`HqPose` の `rammed`）だけ、次のように変えた: `Impact` の中心を胸から足元へ 35% 下げる、大きさ ×0.85、放射線 0.45・輪 0.55、体のぴかっ（`Flash`）を 1→0.55。地面の輪（`Slam`）と、精に当たるときの演出はそのまま。結果は味方10着弾で最大 0.25〜0.50・平均 0.27〜0.32（3回）、目が読める（B の 0.50 は髪とほおが淡いため）。しきい値を 0.60 / 平均 0.40 に締めた。手応えは少し軽くなる（ねらった交換）。端末での見え方と人の試遊は未確認。
- `RT_WATCHDOG_CAPTURE=1` で、着弾ごとに一番白いフレームの顔の切り抜きを `unity/Logs/hq/private/watchdog/` に出す（原画が写るので外へ出さない）。ログの `WATCHDOG` 行に、着弾ごとの最大・時間・フレームごとの値が出る。
- 光を足したら、この検査と §7.2 の目視の両方を通す。しきい値を緩めて通さない。緩める必要があると思ったら、コマを並べて Human に見せる。

### 5.5 新しい形を足す手順

1. `HqVfx.shader` の `shape()` に `if (id < N.5) { ... }` を足す。入力は −1..1 の `p`、進行度 `k`（0→1）、粒ごとの `seed`。返すのは（濃さ, 白さ）。**最後の形は `if` なしの波括弧**なので、その手前に挿す。
2. `HqVfx.cs` の定数に `名前=N` を足す。
3. レシピから `Emit(名前, ...)`。

## 6. 数字と HP（`HqJuice`）

- ダメージ数字は Field 上の UI Text。命中の瞬間に対象の頭上へ出し、1.7 倍で弾んで 0.95 秒で消える。
- 色で意味を分ける: 味方が受けた = 赤、敵に与えた = 黄、反撃 = 金、回復 = 緑。輪郭は濃い色で太く（2.4pt）、下に影。
- **白い数字は使わない**（閃光と重なって消える）。位置は体の上端。体の中央に出すと閃光に埋もれる。
- HP バーは Core の値どおりに即座に縮め、失った分だけ淡い色で 0.35 秒残してから減らす。

> 教訓: 数字は長いあいだ **一度も画面に出ていなかった**。Text の枠の高さより行の高さが大きく、`VerticalWrapMode.Truncate` で丸ごと切り落とされていた。テストは「ラベルが作られたか」しか見ておらず通っていた。**作ったものは必ず絵で見る**（§7）。

## 7. 確かめ方（ここを省かない）

### 7.1 手順

```bash
# Unity を他で開いていないことを確認してから（同じ project を同時に開かない）
RT_GFX_CAPTURE=3 [RT_GFX_ENCOUNTER=2] <Unity 6000.3.25f1> -batchmode -projectPath unity \
  -runTests -testPlatform PlayMode -testFilter RogueTactics.Tests.PlayMode.GfxPresentationTests \
  -testResults <out>.xml -logFile <out>.log
```

- 撮るのは戦闘だけの検証用 scene `MobileG1`、方針は「攻める」固定。`RT_GFX_ENCOUNTER=<番号>` は撮るときだけ効き、その戦闘を最初の部屋で撮る（部屋の移動は飛ばすので流れの検査ではない。矢は 2 で撮れる）。
- `unity/Logs/hq/private/gfx/` は**実行のたびに丸ごと消える**。残したいコマは先に移す。合否を見る全件の実行は撮影と別に回す（[HANDOFF.md](HANDOFF.md) §6）。

- `RT_GFX_CAPTURE=N` で N フレームごとに `unity/Logs/hq/private/gfx/f####_e##_種別.jpg`（780×1688）を出す。Git には入らない場所。原画が写るので外へ出さない。
- 見たい出来事のコマを並べて1枚にして見る（ffmpeg の `crop` + `tile`）。**JPEG のまま**並べる。PNG に落とすと色が潰れて判断を誤る。
- 盤面は 390×844 基準で y=410〜910 付近（撮影画像は 2 倍の 780×1688 なので y=820〜1820）。まず実寸の全画面で見て、その後で拡大する。

### 7.2 絵を見るときの確認項目

出来事1件ごとに、コマを順に見て次を確かめる。

1. 溜めのコマだけ見て、**誰が動こうとしているか**分かるか
2. 当たりのコマで、**誰に当たったか**分かるか（対象が白い円で消えていないか）
3. 当たりの直後に**数字が読めるか**（色と位置）
4. 攻撃した側は元の位置に戻っているか
5. 対象の顔は歪んでいないか、原画と同じ人物に見えるか
6. 余韻が 0.5 秒以内に消え、次の出来事と重なっていないか
7. HP バー・足元の表示が演出で隠れたままになっていないか

### 7.3 自動テストの位置づけ

- PlayMode は 28 件（うち撮影専用の1件は普段スキップ）が通る状態が基準（PR #24 の遺物・泉、PR #25 の階の景色、予告の範囲と退く、報酬の台座の確認を足した後。2026-11-18、S1-1・S1-13 と敵の見た目の一覧 `GfxSpiritGalleryTests` の後。重なりの検査を `MobileG1InteractionTests.CheckActorReadability`＝「手前の塗られた画素が奥の顔の部位の中心を隠さず、半分以上見える」に置き換え、19/19 を3回連続で確認）。1件でも落ちたら不具合として調べる。演出は顔の画素を覆いうるので、この検査は演出の変更で落ちることがある。
- テストは「壊していないこと」しか保証しない。「良く見えること」は §7.2 と人の目でしか分からない。実機・Simulator・人の試遊は未実施。

## 8. よくある失敗と直し方

| 症状 | 原因 | 直し方 |
|---|---|---|
| 攻撃しても何も起きていないように見える | 動きも光も小さい。溜めと当たりの差がない | 踏み込みを相手に重なるまで伸ばす。当たりに暗い暈と放射線を足す |
| 当たった相手が見えなくなる | 白い芯が大きい・長い | 半径 1.5 以下、0.12 秒以下 |
| エフェクトが薄い・白っぽい | 白い石の上に白い光 | 暈を先に敷く。外側をキャラの色にする |
| キャラがゴムのように見える | 脚や胴の骨を回している、伸縮が大きい | Root を丸ごと動かす。伸縮 ±10% 以内 |
| 顔が歪む | 隣の骨の影響が顔に届いている | Head の Strength を上げる／隣の Radius を下げる |
| 配置や重なりのテストが落ちた | 測られる物（mesh・Transform・カメラ）を動かした | シェーダーの頂点ずらしに置き換える（§2.2） |
| 数字やラベルが出ない | Text の枠で切り落とされている | Overflow にする。絵で確認する |
| 演出と HP の変化がずれる | 当たりを `t=duration` 以外に置いた | 発射時刻 + 飛行時間 = duration に組み直す |
| 倒れた仲間が消えてしまう（シロが倒れると盤から居なくなる） | 倒れたコマは表示側で隠され、測られなくなる | 隠す処理はそのまま。測られない別の写し（`"Fallen rest <id>"`）を最後の姿勢で置く（§3.3） |
| 写した素材が見えない（何も描かれない） | `new Material(元)` は実行中に `SetVectorArray` した配列を写さない。骨が全部ゼロになり、頂点が1点に潰れる | `_BoneX`・`_BoneY`・`_Mirror` を明示的に写す |
| 倒れた仲間が暗い影の塊に見える | 色を暗く・青く寄せすぎた | `_Color` は (.84, .86, .94, 1)。暗くするより、少しだけ色を抜く |
| 一時停止しても光が動く | `Time.deltaTime` を直接使った | `Paused` を見て dt を 0 にする（各 `Tick` の入口） |
