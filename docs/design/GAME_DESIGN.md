## 1. 製品の芯

> 自分の予想を仲間に託し、その戦いから理解を深め、次の可能性を試すRPG。 **[確定]**

プレイヤーは**盤の外からパーティを導く**存在です **[確定]**。4人の仲間は自分で考えて動きます。軍師 E はプレイヤーとは別の、盤の外にいる助言役です（§6.5）。

この一文は体験を評価するための仮説であり、**毎回予想を入力させる操作仕様ではありません**（Human 2026-10-26）。主役は「自動で動く仲間を見守る楽しさ」で、予想や分析は使いたいときに使える形にします。理解済みの戦いを気持ちよく勝つことにも価値があり、毎戦闘で新しい発見を強制しません。

### 体験の三本柱

1. **見守る** — 仲間が自分の判断で動き、守り、倒れる。見ているだけで楽しく、「なぜそうしたか」が画面から読める。これが主役。
2. **託す・ときどき介入する** — 操作するのは一手一手ではなく、方針と必要なときの修正。介入しなくても進む。
3. **次を試したくなる** — 装備や編成や方針を変えると戦い方が変わる。「次はこうしてみたい」が自分の中から出てくる。ゲームは正解を言わず、誘導もしない。

### やらないこと **[確定]**

- ATB、時間制限つきの入力、キャラごとの「こうげき／かいふく」コマンドメニュー
- 別画面の戦闘。探索と戦闘は同じ盤で起きる
- E（軍師）を盤上の駒や「正解を教える役」にすること
- 広告や報酬で修正回数を増やすこと
- 横画面 UI
- 仲間の連携に毎回プレイヤーの承認を要求すること
- AI が「変化を見せるためだけに」戦術を変えること。再評価して変えない、も正しい結果
- 有料素材・外部委託での制作（現行の制作方針）

### 成功の定義

コードが動く・テストが通る・画面が魅力的・遊んで楽しい、の4つは別々に評価します。成立を確かめる問いは共有資料 §11 の6つです（すべて人の非誘導の自由試遊が必要。現時点で未取得）。

1. 仲間が自動で戦う姿を見ているだけで、楽しいと感じる瞬間があるか
2. 自分から仲間の行動を変えたいと思うか
3. 介入の結果を見て、別の行動や構成を試したくなるか
4. 説明を読み込まなくても、誰が何をして、なぜ結果が変わったか分かるか
5. キャラの可愛さ・動き・UI が、続けたい気持ちを高めるか
6. 自動のテンポを保ったまま、判断したい場面で操作できるか

本 branch のグラフィック作業が直接ねらうのは 1・4・5 です。

## 3. 遊びの構造

### 3.1 三つの輪

```
遠征（20〜30分）  ── 階を降りる。何を持ち帰り、何を学んだか
  └ 階（5〜8分）    ── 部屋を進む。どの守り手にどの順で挑むか
      └ 戦い（60〜90秒）── 読む → 託す → 予想する → 見守る → 振り返る
```

### 3.2 戦いの一周（最小単位）

| 段階 | プレイヤーがすること | 画面が見せるもの | 状態 |
|---|---|---|---|
| 読む | 盤を見る | 全員の「次の一手」の矢印（一巡）、行動順、危ないマス | [実験中] |
| 託す | 一人の方針を選ぶ | 選んだ方針で矢印が変わる | [確定]（方針の種類は実験パラメータ） |
| 予想する | 任意。何もしなくてよい | 入力欄は出しゃばらない。書かなくても進む | [実験中]（強制しない、は Human 2026-10-26） |
| 見守る | 何もしない。危機で止まったら一度だけ修正できる | Core のイベントを一つずつ演出。危機は自動で止まる | [確定] 修正は encounter ごと1回 / [実験中] 危機停止 |
| 振り返る | 任意。見たいときだけ | 予想・実際・前回との違いを記録として残す | [実験中] |

入力は1戦あたり 0〜3回（何もせず任せて勝つのも正しい遊び方）。「見守る」時間が体験の大半を占めるので、**演出の質がそのままゲームの質**になります。グラフィックを本指示の中心に置く理由はここです。

### 3.3 階と遠征 **[提案]**

広いダンジョン（部屋と通路を実際に探索できる広がり）の方向は Human が 2026-10-25 に選んでおり、8部屋の探索試作があります。ただし完成仕様ではなく、広域化とフィールド追加制作の優先度は下げられています。リリースに向けた段階を提案します。数（階数・部屋数）はどれも未決定で、コンセプト画の「12F / 15F」は絵の内容であり仕様ではありません。

| 段階 | 内容 | 目的 |
|---|---|---|
| S1 縦切り（現状の延長） | 1階・3戦。演出・UI・音を製品品質に | 「見守る」が気持ちよいかを人で確かめる |
| S2 アルファ | 3階。敵 4種、遺物 6種、階ごとに盤の形が違う | 「次を試す」が階をまたいで続くか |
| S3 リリース候補 | 1遠征 5階＋守護者（ボス）1体。記録・設定・チュートリアル無しの導入 | 20〜30分の遠征として成立するか |

ダンジョン生成方法は未決です。本書の提案は、手で置いた部屋の並べ替え（seed で決定）で、完全な自動生成はしないこと。理由: 学びを試すには「似ているが違う」盤が要り、無作為な盤は因果を読みにくくするため。

## 4. 戦闘ルール

### 4.1 いまある規則（Core の事実）

- 5×5 の盤。離散ターン。行動順は encounter ごとに固定の列。
- 味方4人・敵2体。役割は Anchor / Protector / Flanker / Support / Enemy。
- 行動は Maintain / Move / Attack / Protect / Heal。Core が意図（Plan）を生成し、合法性を判定する。
- イベントは Action / Move / Protect / Damage / Heal / Counter / Death / End。Presentation はこれを順に描くだけ。
- 方針は現在2つ（シロを守る／敵へ攻める）で、モモに託す。
- 同じ初期状態と入力列からは同じ結果とイベント列が出る（replay hash で固定）。

## 5. 敵の設計 **[提案]**

敵は「強さ」ではなく「一つの読み」を教える存在として作ります。1体につき教えることは一つ。

| 敵 | 見た目 | ふるまい | 教えること | 段階 |
|---|---|---|---|---|
| 苔の精 | 緑の丸い体に双葉 | 一番近い味方へまっすぐ来る | 守り手の立ち位置で被害が変わる | S1（実装済みの見た目） |
| 花の精 | 紫の体に五弁の花 | 体力が一番低い味方を狙う | 「誰が狙われるか」は矢印で読める | S1（実装済みの見た目） |
| 茸の番人 | 赤い傘の白い体 | 動かず、隣を守る（敵側の Protect） | 順番を変えれば守りは崩せる | S2 |
| 影こうもり | 紫の羽 | 2マス飛び越えて後衛へ | 支援役を孤立させない | S2 |
| 遺跡の守護者 | 石と蔦の大型 | 2ターン先の範囲攻撃を予告 | 危機停止での修正の使いどころ | S3 |

見た目の方針は GRAPHICS.md §5。どの敵も「丸い・目が大きい・怖くない」。

## 6. 成長と報酬 **[提案]**

共有資料の方向は「ハクスラ的な成長・装備変更」「装備や編成を変えると戦術が変化する」「仲間自身も成長し、以前とは違う連携を見せる」です。体系（装備・レリック・スキル・個人とパーティの成長・ラン間の引き継ぎ）はすべて未決なので、ここでは原則だけ提案します。

- **原則**: 成長と装備は「数字が大きくなる」より「**戦い方が変わる**」を先に置く。攻撃力+1 だけの報酬は、理解して勝ったのか強くなって勝ったのかを分からなくするので主役にしない。数値成長を入れるかどうか自体は Human 判断。
- **レリック**: 階の報酬で2つから1つ選ぶ。検証用の候補は「荊棘の護符」（反撃強化）と「巡礼の鈴」（支援強化）で、製品の正式体系ではない。選んだ結果が次の戦いの仲間の動きに現れること。
- **装備・編成**: 変えると仲間の意図（矢印）が目に見えて変わること。演出側は武器種ごとの型（GRAPHICS.md §3）で受ける。
- **記録**: 自分の予想と結果が遠征をまたいで残る。同じ盤に再挑戦したとき、前回の自分の予想が横に出る。
- 遺物は戦闘結果を隠れて変えない。効果はすべて Core の明示的な command と合法性判定を通す **[確定]** の原則に従う。

### 6.5 軍師と合議（長期構想。実装は未確定）

- 軍師 E は盤の外の別枠。仲間の能力と状況から役割分担や作戦を**提案**する。正解を知る存在ではなく、仲間は必ずしも従わない **[確定]（概念）**。
- **統率力**（仲間の自主性を活かして連携を引き出す力）と**影響力**（提案を受け入れてもらう力）は別の概念。数値化は未決。
- 軍師と仲間の考えが違うことは失敗ではない。プレイヤーは仲間の案を支持してもよい。
- 技術の有力方針: AI に毎フレーム結果を決めさせず、合議・経験・判断を構造化した Plan に変換し、Core が決定論的に実行する。現在の G1 の決定論ロジックと、この将来構想を混同しない。高度な推論・人格学習・経験学習は未実装。
- 演出への要求（提案）: 提案と仲間の判断が食い違った瞬間を、長文ではなく表情・小さな吹き出し1つ・矢印の色で読めるようにする。4人同時の長文吹き出しは出さない。

## 7. 見た目と手触り（要約）

詳細は GRAPHICS.md。ここでは全体の決まりだけ。

- **敵**: 丸く、艶があり、怖くない。2階調のトゥーン。
- **演出の約束**: 画面で起きることは必ず Core のイベントが原因。演出が結果や順番を変えない **[確定]**。
- **読みやすさが先**: エフェクトはキャラの顔と HP を隠さない。一撃の演出は 0.9 秒以内に収める。

## 11. リリース品質の基準 **[提案]**

「リリースできる」を主観で終わらせないための物差しです。数値は実機で測ってから確定します（未計測）。

| 観点 | 基準 | 確かめ方 |
|---|---|---|
| 滑らかさ | iPhone 12 相当で 60fps 目標、戦闘中の p95 フレーム時間 20ms 以下 | 実機計測（`HqFrameMetrics` を利用） |
| 起動 | タップから盤が見えるまで 3 秒以内 | 実機計測 |
| 読みやすさ | 腕の長さで、誰が誰に何をするかを 2 秒で言える | 人の試遊 |
| 因果 | 守りで減ったダメージ・反撃・回復を、ログを読まずに説明できる | 人の試遊 |
| 手触り | すべての Core イベントに、予備動作・着弾・余韻の三拍がある | 本 branch の演出表（GRAPHICS.md §4） |
| 破綻なし | 1時間の連続プレイでクラッシュ・進行不能・表示の食い違いがない | 自動 soak ＋人 |
| 一貫性 | 同じ入力からは必ず同じ結果（replay hash 一致） | 既存 EditMode テスト |
| 音 | 無音の Core イベントがない | 対応表の網羅チェック |

## 13. 主なリスク

| リスク | 兆候 | 手当て |
|---|---|---|
| 見ているだけで退屈 | 試遊者が早送りを連打する | 一撃を短く濃く（0.9秒以内）、危機停止で必ず手番が来る、早送りは 2倍まで |
| 因果が読めない | 「なぜ倒れたか分からない」 | 着弾の瞬間に数字・盾・光を重ねる。振り返りで前回との差を1行で出す |
| 1枚絵の限界・「うにょうにょ」 | 大きく動かすと絵が歪み、ゴムのように見える | 脚は変形させない。大きな動きは体全体の剛体的な傾き・弾みとエフェクトで見せる。髪・外套の揺れが同じ印象を与えるなら量を下げるか切る（Human の目で判断）。背面・表情差分は将来の原画追加 |
| 別人に見える | 動かした結果、承認原画の子に見えない | 顔まわりの骨は回転 ±0.06rad 程度に抑える。違和感の報告があれば即その動きを外す |
| 介入しすぎ／しなさすぎ | 手動戦術ゲーム化、または放置ゲーム化 | 介入回数と停止条件は試遊で決める（D2・D6）。演出側は「任せて見ているだけ」で成立する濃さを保つ |
| 見た目が先行して芯が未検証のまま進む | 試遊なしで機能が増える | S1 の人の試遊を S2 着手の条件にする |
| Codex / Claude の同時作業の衝突 | 同じ Unity project の同時起動 | Claude は自分の worktree のみ。`codex/*` には書かない |
