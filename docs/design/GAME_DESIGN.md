この文書は「リリースできる品質の製品」に必要な全体像を一枚にまとめた**設計提案**です。承認済みの事実と、まだ提案であるものを必ず分けて書きます。

| 印 | 意味 |

[提案] を実装で先に埋めないこと。Executor は [確定] と [実験中] の範囲だけを実装し、[提案] は Human が選んだ時点でこの表記を更新します。Notion の Decision Log は今回未確認（Claude 側未認証）なので、Human 判断の出典は Issue / PR 本文に限っています。

## 1. 製品の芯

> 自分の予想を仲間に託し、その戦いから理解を深め、次の可能性を試すRPG。 **[確定]**

プレイヤーは盤の外にいる**軍師**です。4人の仲間は自分で考えて動きます。プレイヤーの仕事は、戦いが始まる前と危ない瞬間に「誰に何を託すか」を一つ選び、どうなるかを予想し、結果を見て次の考えを持つこと。

### 体験の三本柱

1. **託す** — 操作するのは仲間の一手一手ではなく、方針と一度きりの修正。少ない入力に重みがある。
2. **見届ける** — 仲間が自分の判断で動き、守り、倒れる。その一つ一つが「なぜそうなったか」まで画面から読める。
3. **次を試す** — 負けても勝っても「次はこうしてみたい」が自分の中から出てくる。ゲームは正解を言わない。

### やらないこと **[確定]**

- ATB、時間制限つきの入力、キャラごとの「こうげき／かいふく」コマンドメニュー
- 別画面の戦闘。探索と戦闘は同じ盤で起きる
- E（軍師）を盤上の駒や「正解を教える役」にすること
- 広告や報酬で修正回数を増やすこと
- 横画面 UI

### 成功の定義

自動テストの成功や見た目の良さでは成立を主張しません。成立とは、**人が試遊して、頼まれずに方針を変え、その理由を自分の言葉で言えること**です（human play evidence。現時点で未取得）。

## 3. 遊びの構造

### 3.1 三つの輪

```
遠征（20〜30分）  ── 階を降りる。何を持ち帰り、何を学んだか
  └ 階（5〜8分）    ── 部屋を進む。どの守り手にどの順で挑むか
      └ 戦い（60〜90秒）── 読む → 託す → 予想する → 見届ける → 振り返る
```

### 3.2 戦いの一周（最小単位）

| 段階 | プレイヤーがすること | 画面が見せるもの | 状態 |
|---|---|---|---|
| 読む | 盤を見る | 全員の「次の一手」の矢印（一巡）、行動順、危ないマス | [実験中] |
| 託す | 一人の方針を選ぶ | 選んだ方針で矢印が変わる | [確定]（方針の種類は実験パラメータ） |
| 予想する | 任意で一言残す | 入力欄。書かなくても進める | [実験中] |
| 見届ける | 何もしない。危機で止まったら一度だけ修正できる | Core のイベントを一つずつ演出。危機は自動で止まる | [確定] 修正は encounter ごと1回 / [実験中] 危機停止 |
| 振り返る | 予想と結果を見比べる | 予想・実際・前回との違い | [実験中] |

入力は1戦あたり 1〜3回。「見届ける」時間が体験の大半を占めるので、**演出の質がそのままゲームの質**になります。グラフィックを本指示の中心に置く理由はここです。

### 3.3 階と遠征 **[提案]**

現状は 1階・3部屋・3戦の実験構成です。リリースに向けた段階を提案します。数（階数・部屋数）はどれも未決定で、コンセプト画の「12F / 15F」は絵の内容であり仕様ではありません。

| 段階 | 内容 | 目的 |
|---|---|---|
| S1 縦切り（現状の延長） | 1階・3戦。演出・UI・音を製品品質に | 「見届ける」が気持ちよいかを人で確かめる |
| S2 アルファ | 3階。敵 4種、遺物 6種、階ごとに盤の形が違う | 「次を試す」が階をまたいで続くか |
| S3 リリース候補 | 1遠征 5階＋守護者（ボス）1体。記録・設定・チュートリアル無しの導入 | 20〜30分の遠征として成立するか |

階の中身は手で置いた部屋の並べ替え（seed で決定）とし、完全な自動生成はしません。理由: 学びを試すには「似ているが違う」盤が要り、無作為な盤は因果を読みにくくするため。

## 4. 戦闘ルール

### 4.1 いまある規則（Core の事実）

- 5×5 の盤。離散ターン。行動順は encounter ごとに固定の列。
- 味方4人・敵2体。役割は Anchor / Protector / Flanker / Support / Enemy。
- 行動は Maintain / Move / Attack / Protect / Heal。Core が意図（Plan）を生成し、合法性を判定する。
- イベントは Action / Move / Protect / Damage / Heal / Counter / Death / End。Presentation はこれを順に描くだけ。
- 方針は現在2つ（シロを守る／敵へ攻める）で、モモに託す。
- 同じ初期状態と入力列からは同じ結果とイベント列が出る（replay hash で固定）。

| ID | 名前 | Core の役割 | 絵 | 演出上の型（本 branch で実装） |

| A | シロ | Anchor（守られる要） | 白髪・青い魔女帽・杖 | 詠唱型: 足元に陣、杖先に光を集めて放つ |
| B | モモ | Protector（守り手） | 桃色・花の盾・メイス | 盾型: 盾を突き出して構える／メイスを振り下ろす |

## 5. 敵の設計 **[提案]**

敵は「強さ」ではなく「一つの読み」を教える存在として作ります。1体につき教えることは一つ。

| 敵 | 見た目 | ふるまい | 教えること | 段階 |
|---|---|---|---|---|
| 苔の精 | 緑の丸い体に双葉 | 一番近い味方へまっすぐ来る | 守り手の立ち位置で被害が変わる | S1（実装済みの見た目） |
| 花の精 | 紫の体に五弁の花 | 体力が一番低い味方を狙う | 「誰が狙われるか」は矢印で読める | S1（実装済みの見た目） |
| 茸の番人 | 赤い傘の白い体 | 動かず、隣を守る（敵側の Protect） | 順番を変えれば守りは崩せる | S2 |
| 影こうもり | 紫の羽 | 2マス飛び越えて後衛へ | 支援役を孤立させない | S2 |
| 遺跡の守護者 | 石と蔦の大型 | 2ターン先の範囲攻撃を予告 | 危機停止での修正の使いどころ | S3 |

見た目の方針は GRAPHICS.md §5。どの敵も「丸い・目が大きい・怖くない」。

## 6. 成長と報酬 **[提案]**

数値を積み上げる成長（Lv、攻撃力+1）は入れません。理由: 数値が上がると「理解したから勝てた」のか「強くなったから勝てた」のかが分からなくなり、芯の仮説を確かめられなくなるため。

- **遺物**: 階に1つ。数値ではなく**選べる介入や見える情報**を変える。例: 「見張りの羽根 — 敵の意図が2手先まで見える」「誓いの紐 — 修正で二人を入れ替えられる」。
- **記録**: 自分の予想と結果が遠征をまたいで残る。同じ盤に再挑戦したとき、前回の自分の予想が横に出る。
- 遺物は戦闘結果を隠れて変えない。効果はすべて Core の明示的な command と合法性判定を通す **[確定]** の原則に従う。

## 7. 見た目と手触り（要約）

詳細は GRAPHICS.md。ここでは全体の決まりだけ。

- **世界**: 陽の当たるクリーム色の石、蔦と小花、滝、青と金の旗。空に浮く遺跡。
- **キャラ**: 承認済みのちび絵4人。顔・目・肌・衣装の色は変えない **[確定]**。新しい絵は描き足さず、1枚絵をやわらかい骨格で動かす。
- **敵**: 丸く、艶があり、怖くない。2階調のトゥーン。
- **演出の約束**: 画面で起きることは必ず Core のイベントが原因。演出が結果や順番を変えない **[確定]**。
- **読みやすさが先**: エフェクトはキャラの顔と HP を隠さない。一撃の演出は 0.9 秒以内に収める。

## 8. 画面と操作（要約）

詳細は IMPLEMENTATION_SPECS.md §4。

- 縦持ち・390×844pt 基準 **[確定]**。盤が画面の 65〜75%、下に4人のカード、上の隅に遺跡名と小地図。
- 片手・親指で届く下 1/3 に主操作を置く。タップ領域は 44pt 以上。
- 通常画面に開発用ボタンを出さない。開発モードは設定の奥。
- 1戦の入力は「方針を選ぶ → 託す」の2タップが最短。予想メモは任意。

## 9. 音 **[提案]**

現在、音は一切ありません。リリース品質には必須です。設計は IMPLEMENTATION_SPECS.md §5。要点は、**演出と同じく Core のイベントを原因にして鳴らす**こと、そして着弾の瞬間（HP が変わる瞬間）に音の頭を合わせることです。

## 10. 収益と公開

- **[確定]** 広告・報酬で修正回数を増やさない。課金・有料サービス・解析・テレメトリの追加は Human の明示許可が必要。
- **[提案]** 買い切り（無料で1階、遠征全体は一度の購入）。理由: 「見届ける」ゲームは広告の割り込みと相性が悪く、時間を売る設計は芯と矛盾する。価格・配信形態は USER_DECISION。
- 現在の配布は owner のみの Internal TestFlight。外部テスター・公開は Human の許可が必要。

## 11. リリース品質の基準 **[提案]**

「リリースできる」を主観で終わらせないための物差しです。数値は実機で測ってから確定します（未計測）。

| 観点 | 基準 | 確かめ方 |
|---|---|---|
| 滑らかさ | iPhone 12 相当で 60fps 目標、戦闘中の p95 フレーム時間 20ms 以下 | 実機計測（`HqFrameMetrics` を利用） |
| 起動 | タップから盤が見えるまで 3 秒以内 | 実機計測 |
| 読みやすさ | 腕の長さで、誰が誰に何をするかを 2 秒で言える | 人の試遊 |
| 因果 | 守りで減ったダメージ・反撃・回復を、ログを読まずに説明できる | 人の試遊 |
| 手触り | すべての Core イベントに、予備動作・着弾・余韻の三拍がある | 本 branch の演出表（GRAPHICS.md §4） |
| 破綻なし | 1時間の連続プレイでクラッシュ・進行不能・表示の食い違いがない | 自動 soak ＋人 |
| 一貫性 | 同じ入力からは必ず同じ結果（replay hash 一致） | 既存 EditMode テスト |
| 音 | 無音の Core イベントがない | 対応表の網羅チェック |

## 13. 主なリスク

| リスク | 兆候 | 手当て |
|---|---|---|
| 見ているだけで退屈 | 試遊者が早送りを連打する | 一撃を短く濃く（0.9秒以内）、危機停止で必ず手番が来る、早送りは 2倍まで |
| 因果が読めない | 「なぜ倒れたか分からない」 | 着弾の瞬間に数字・盾・光を重ねる。振り返りで前回との差を1行で出す |
| 1枚絵の限界 | 大きく動かすと絵が歪む | 回転は ±1rad 以内、大きな動きは体全体とエフェクトで見せる。背面・表情差分は将来の原画追加（Human 判断） |
| 見た目が先行して芯が未検証のまま進む | 試遊なしで機能が増える | S1 の人の試遊を S2 着手の条件にする |
| Codex / Claude の同時作業の衝突 | 同じ Unity project の同時起動 | Claude は自分の worktree のみ。`codex/*` には書かない |
